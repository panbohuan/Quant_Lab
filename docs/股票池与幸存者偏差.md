# 股票池与幸存者偏差：为什么"免费数据"会让回测虚高，以及怎么办

> 本文回答一个几乎所有免费数据回测都会踩的坑：
> **用"当前的股票列表"去回测历史，收益会被系统性高估。**
>
> 结论先说：**改用"全市场 + 过滤条件"只能减轻、不能消除这个问题；真正的解法是改用申万行业指数。**
>
> 相关代码：`btlab/datasource.py` 的 `load_all_stocks()` / `load_market_universe()` / `load_sw_universe()`

---

## 一、什么是幸存者偏差（Survivorship Bias）

**幸存者偏差 = 你只看到了"活到今天"的样本，却用它去推断"当年全体"的规律。**

经典例子：二战时统计返航飞机的弹孔，发现机翼弹孔最多——于是有人主张加固机翼。
但真正的结论应该是**加固机身**：因为机身中弹的飞机**根本没飞回来**，不在样本里。

放到 A 股回测上：

| 时间 | 真实世界 | 你的回测里 |
|---|---|---|
| 2015 年 | 有 2800 只股票在交易 | 你只有"2026 年还在的 5000 只"的名单 |
| 2015–2026 期间 | 有 200+ 只退市 / 被并购 / 长期停牌 | **这些股票在回测里根本不存在** |
| 结果 | 真实可投资集合包含了"会归零的股票" | 你的集合**只剩活下来的** → 收益虚高 |

**一句话**：`ak.stock_zh_a_spot_em()`、`ak.stock_info_a_code_name()`、`get_index_stocks()` 这些接口返回的都是
**"今天"的名单**。用它去回测 2015 年，你等于**提前知道了哪些公司能活下来**——这本身就是一种未来函数。

---

## 二、为什么"改用全市场 + 过滤条件"解决不了

很自然的想法是：**别用沪深300成分股（那本来就是被挑出来的大票），改成全市场 + 自己加过滤条件。**

**这个改进方向是对的，但它解决的是另一个问题：**

| | 指数成分股池 | 全市场池 |
|---|---|---|
| 样本范围 | 只有 300 只大盘股 | 5000+ 只，更接近"真实可投资集合" |
| **入选偏差**（只挑了大票/好票） | ❌ 严重 | ✅ 基本消除 |
| **退市偏差**（退市的票不在名单里） | ❌ 有 | ❌ **一样有** |

**关键点**：全市场名单**依然只包含"今天还活着"的公司**。历史上涨到一半退市的那批股票，
在全市场名单里**同样找不到**。所以：

> **全市场池 ≠ 无偏。它把"指数成分股偏差"解决了，但"退市偏差"一分没少。**

真正的修复需要**历史时点的成分股/全市场名单**（point-in-time universe）——免费数据源基本不提供，
只有聚宽这类平台能在任意历史日期返回 `get_index_stocks(date)`。

---

## 三、过滤条件：必须用"当时可知"的信息

即使只用全市场池，**过滤条件也必须小心**，否则会把偏差从一个地方挪到另一个地方。

| 过滤条件 | 是否可用 | 原因 |
|---|---|---|
| 截至 t 日的 20 日均成交额 ≥ X | ✅ **可以** | t 日就能算出来（时点内可得） |
| 截至 t 日已上市满 N 个交易日 | ✅ **可以** | 用 K 线根数判断，天然时点内可得 |
| 截至 t 日剔除停牌（当天无行情） | ✅ **可以** | 当天有没有数据是已知的 |
| **今天的 ST 名单** | ❌ **不可以** | 今天被 ST 的公司，2019 年可能经营正常 → 引入了新的未来函数 |
| **今天的总市值 / 今天的成分股** | ❌ **不可以** | 同理，是用今天的状态倒推过去 |

**一句话**：**判断"能不能用"，就问一句——"这个信息在 t 日当天，我拿得到吗？"**

> 本仓库的实现遵循了这条规则：
> `load_market_universe(min_bars=120)` 用的是"K 线根数 ≥ 120"（= 上市满 120 个交易日），
> 属于时点内可得；**故意没有**加入"当前 ST 名单"这类会引入未来函数的过滤。

## 四、三套方案对比与推荐

| 方案 | 幸存者偏差 | 可交易性 | 数据可得性 | 本仓库函数 |
|---|---|---|---|---|
| ① 指数成分股（现状） | ❌ 入选偏差 + 退市偏差 | ✅ 直接买成分股 | ✅ 免费 | `load_index_members()` |
| ② 全市场 + 时点内过滤 | ⚠️ 仅剩退市偏差 | ✅ 直接买股票 | ⚠️ 免费源只给当前名单 | `load_market_universe()` |
| ③ **申万行业指数** | ✅ **无幸存者偏差** | ⚠️ 指数不可直接交易（需 ETF/成分股组合） | ✅ 免费（1999 年起） | `load_sw_universe()` |

### 为什么推荐方案 ③

**行业指数是"连续发布"的**：指数会定期调整样本股（把差公司剔除、把好公司纳入），
但**指数点位序列不会消失**——它已经反映了"当时真实的行业表现"，包括那些后来被剔除的公司。

所以：**用行业指数做历史回测，不存在"只买到了活下来的公司"这个问题。**

**代价**：指数不可直接买卖。落地有两条路：

1. **用行业 ETF**（推荐）：目前有 20+ 个申万一级行业有对应 ETF，跟踪误差可控；
2. **用行业成分股组合**：那就又回到了"需要历史成分股"的老问题（免费源做不到）。

> 本仓库的 `bt_a02_sector_rotation`（行业轮动）就是这个思路的实现——
> 它在文档里也如实标注了"指数不可直接交易"。

### 结论（分层使用）

```
第 1 层：资产/行业配置  →  申万行业指数（load_sw_universe）   ← 无幸存者偏差
第 2 层：行业内选股    →  有历史成分股就用（聚宽）；免费源没有 → 只能停在第 1 层
第 3 层：全市场选股    →  load_market_universe（样本更广，但退市偏差仍在，需在文档里标注）
```

## 五、怎么用（代码）

### 5.1 全市场抽样池（方案 ②）

```python
from btlab.datasource import load_market_universe, load_daily
from btlab.runner import run_strategy

# 全市场随机抽 300 只 + 剔除上市不足 120 个交易日的
data = load_market_universe(start='2018-01-01', end=None,
                            sample=300, min_bars=120, seed=42)
data['__CAL__'] = load_daily('000300', start='2018-01-01')   # 交易日历
run_strategy(MyStrategy, data, benchmark='000300')
```

> `sample` 控制数据量：**300 → 约 3~8 分钟**（首次下载）；`None` = 全市场（5000+ 只，非常慢）。
> 抽样用固定 `seed`，保证结果可复现。

### 5.2 申万行业指数池（方案 ③，推荐）

```python
from btlab.datasource import load_sw_universe, load_daily
from btlab.runner import run_strategy

data = load_sw_universe(start='2010-01-01', end=None, min_bars=61)   # 31 个行业指数
data['__CAL__'] = load_daily('000300', start='2010-01-01')
run_strategy(SectorRotation, data, benchmark='000300')
```

**会打印**：`申万一级行业指数：31/31 个可用（指数不可直接交易，落地需行业 ETF）`

> **实测数据（2026-10-09，akshare 1.19.1）**：
> `load_all_stocks()` → **5573 只**（约 8 秒）；
> `load_sw_universe(start='2020-01-01')` → **31/31 个行业指数**（约 2 分钟，含逐行业下载；有缓存后秒开）。
> 示例：`农林牧渔` 2020-01-02 ~ 2026-10-09 共 1628 个交易日。

### 5.3 只看代码列表（自检用）

```python
from btlab.datasource import load_all_stocks
df = load_all_stocks()
print(len(df), '只')          # 约 5000+（注意：这是"今天"的名单）
print(df.head())
```

## 六、怎么知道偏差有多大？（可做的实验）

**同一套策略、同一段区间，只换股票池，对比结果**——差异就是偏差的量级。

```python
# 版本 A：指数成分股（入选偏差重）
codes = load_index_members('000300')[:40]
dataA = load_universe(codes, start='2018-01-01')

# 版本 B：全市场抽样 + 时点内过滤（入选偏差轻，退市偏差仍在）
dataB = load_market_universe(start='2018-01-01', sample=300, min_bars=120)

# 分别跑同一个策略，比较：累计收益、最大回撤、夏普
```

**预期结果**：对**小市值 / 动量**这类依赖"挑股票"的策略，
**版本 B 的收益会明显低于版本 A**——因为可选的"垃圾股"更多了，
而 A 里那些"活下来的大票"天然更安全。**这个差异就是幸存者偏差的量化体现。**

> ⚠️ 注意：跑完 B 后**还不能**宣称"已经修正了幸存者偏差"——因为退市股票仍然缺失。
> 真正的无偏结果只能靠**历史时点成分股**（付费/平台数据）或**改用行业指数**（方案 ③）。

## 七、已知限制与后续

| 限制 | 说明 | 可能的改进 |
|---|---|---|
| 退市偏差无法用免费数据消除 | 免费源不提供历史全市场名单 | 改用行业指数（方案③）或接付费数据源 |
| 抽样会引入随机性 | `load_market_universe(sample=N)` | 固定 `seed`；或改用分层抽样（按行业/市值） |
| 未做 ST 过滤 | 需要用"当时的 ST 状态"，免费源难拿 | 用股票**当时的名称**做近似（名称含 ST/*ST） |
| 未做流动性门槛 | 小市值股票真实成交额很低，回测会高估 | 加"截至 t 日 20 日均成交额"过滤（需先完善数据层） |
| 行业 ETF 的跟踪误差 | 方案③落地时的损耗 | 选规模大、费率低的 ETF；或做 ETF 溢价过滤 |
