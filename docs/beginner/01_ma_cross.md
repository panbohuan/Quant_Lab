# 策略 1：双均线趋势跟踪（MA Cross）

> 策略类型：技术指标择时（单标的） ｜ 难度：★☆☆☆☆ ｜ 前置知识：Python 基础、K线/均线概念

## 一、核心思路

**均线（MA，Moving Average）** 是过去 N 个交易日收盘价的算术平均值，用来平滑价格波动、看清趋势方向。它的计算非常简单：

$$MA_N = \frac{\text{最近 } N \text{ 天的收盘价之和}}{N}$$

例如 5 日均线，就是把最近 5 天的收盘价加起来除以 5。每天收盘后都会算出一个新的 5 日均线值，把这些值连起来，就形成一条"跟随价格、但更平滑"的曲线。

**为什么要有短期和长期两条均线？**

- **短期均线**（如 5 日）只用了很少几天的数据，对价格变化反应**快**，紧跟价格；
- **长期均线**（如 20 日）平均了更多天的数据，更**平滑**，代表中期趋势方向。

两条均线的**相对位置**和**交叉**，就构成了本策略的买卖信号：

- **金叉（买入信号）**：短期均线从下方向上穿过长期均线。意味着短期价格开始强于长期趋势，可能是一轮上涨的启动；
- **死叉（卖出信号）**：短期均线从上方向下穿过长期均线。意味着短期走弱，可能转跌。

这就是**趋势跟踪（Trend Following）**的雏形：**不预测涨跌，只跟随趋势**。涨了就跟进去吃利润（让利润奔跑），跌了就离场截断亏损。它牺牲了"抄底逃顶"的精准度，换取"不错过大行情、不被深度套牢"的稳健性。

> 给新手的直觉：想象你在观察一列火车（价格）。均线就是"火车头的平均位置"。当快的车头（短期均线）超过了慢的车厢（长期均线），说明车在加速前进，你上车；反过来车头落后了，说明在减速，你下车。

## 二、算法结构（分步拆解）

```
每天 14:50 触发 trade(context)
   │
   ├─ 1. 取过去 21 个交易日的收盘价（attribute_history）
   │      （21 = 长均线周期 20 + 1，多取 1 根用来判断"昨天"是否交叉）
   │
   ├─ 2. 计算"今天"和"昨天"的 5 日、20 日均线
   │
   ├─ 3. 判断交叉：
   │      金叉（今天短>长 且 昨天短<=长）→ order_target_value 满仓买入
   │      死叉（今天短<长 且 昨天短>=长）→ order_target_value 清仓
   │
   └─ 4. log.info 记录操作
```

关键点在于第 3 步：判断"交叉"不能只看今天谁大谁小，必须**同时看今天和昨天**。只有"今天反超了昨天"才叫交叉，否则只是"一直大于/一直小于"。

## 三、代码逐段详解 + 函数解析

### 3.1 `initialize(context)` —— 策略的"入口"

聚宽回测引擎启动时会**先调用一次** `initialize`，用于配置全局设置和注册定时任务。`context` 是一个贯穿全局的上下文对象，里面保存了账户、持仓、当前时间等信息。

```python
def initialize(context):
    set_benchmark('000300.XSHG')
    set_option('use_real_price', True)
    set_order_cost(OrderCost(...), type='stock')
    run_daily(trade, time='14:50')
```

**算法逻辑**：回测 = 从起点到终点，按时间顺序一步步"重演"历史行情，每一步调用你的函数。`initialize` 就是"第 0 步"，负责把所有规则（基准、成本、什么时候做什么）先声明好。

### 3.2 `set_benchmark(security)` —— 设定基准

设定一个**比较基准**，回测结果会同时画出"你的策略 vs 基准"的收益曲线，用来判断策略是否跑赢大盘。

```python
set_benchmark('000300.XSHG')   # 以沪深300指数为基准
```

- **其他用法**：`set_benchmark('000905.XSHG')`（中证500）、`set_benchmark('000001.XSHG')`（上证指数）等任何指数代码。
- 基准只影响**对比展示**，不影响你的实际交易。

### 3.3 `set_option('use_real_price', True)` —— 真实价格模式

开启后，回测使用**动态复权（真实价格）**，让成交价更贴近实盘。这是聚宽推荐的标准设置，几乎所有策略都应在 `initialize` 里开启。

```python
set_option('use_real_price', True)
```

> 复权（重要概念）：股票会分红、送股、拆股，导致股价"跳空"（看似暴跌实则只是除权）。不复权的话，均线会因除权跳空产生虚假信号。聚宽的复权处理会自动把这些因素剔除，保证价格连续可比。

### 3.4 `set_order_cost(...)` —— 交易成本（重要！）

真实交易是有成本的，忽略它会导致回测收益**严重虚高**。`OrderCost` 常用参数：

| 参数 | 含义 | 本例取值 | 说明 |
|------|------|----------|------|
| `open_tax` | 买入印花税 | 0 | A股买入不收印花税 |
| `close_tax` | 卖出印花税 | 0.001（0.1%） | A股卖出收 0.1% |
| `open_commission` | 买入佣金 | 0.0003（0.03%） | 券商佣金，万三 |
| `close_commission` | 卖出佣金 | 0.0003 | 同上 |
| `close_today_commission` | 当日回转佣金 | 0 | T+0 卖出佣金（股票 T+1，用不到） |
| `min_commission` | 单笔最低佣金 | 5 元 | 券商普遍有"最低5元" |

```python
set_order_cost(OrderCost(open_tax=0, close_tax=0.001,
                         open_commission=0.0003, close_commission=0.0003,
                         min_commission=5), type='stock')
```

- `type` 参数：`'stock'`（股票）、`'fund'`（基金）、`'futures'`（期货）等，不同品种手续费规则不同。
- **为什么重要**：一个年换手 10 倍的策略，若忽略手续费，回测收益可能虚高 5~10 个百分点。专业的回测必须算成本。

### 3.5 `set_slippage(FixedSlippage(0.02))` —— 滑点

滑点 = 你"想成交的价格"和"实际成交价格"之间的差。`FixedSlippage(0.02)` 表示每次成交价格比理想价差 0.02%。

- **为什么有滑点**：真实市场中，你下买单会推高价格、下卖单会压低价格（冲击成本），尤其是大单。回测里加滑点就是模拟这种"市场冲击"。
- **其他滑点类型**：`PriceRelatedSlippage`（按价格比例，更常用）、`StepRelatedSlippage`（按最小变动价位）。

### 3.6 `log.set_level('order', 'error')` —— 日志级别

`log` 是聚宽的日志模块。这行代码把"下单相关日志"的级别设为 `error`，即只输出错误，过滤掉大量"每次下单成功"的噪声信息，让回测日志更清爽。

- 常用级别：`'debug'` < `'info'` < `'warn'` < `'error'`。
- 其他用法：`log.info('买入 %s', code)` 输出自定义日志，`log.warn(...)` 输出警告。

### 3.7 `g` 全局变量对象

`g` 是聚宽提供的**全局变量容器**，在整个回测期间一直存在，用来保存策略参数和跨函数共享的状态。

```python
g.security = '510300.XSHG'   # 交易标的
g.short = 5                  # 短期均线周期
g.long = 20                  # 长期均线周期
```

- **为什么用 `g` 而不是普通全局变量**：聚宽引擎对每个交易日的函数调用做了隔离，普通全局变量可能丢失或被重置，而 `g` 是官方提供的持久化容器。
- 你可以在任何函数里通过 `g.xxx` 读写这些参数。

### 3.8 `run_daily(func, time=...)` —— 定时任务

这是聚宽最常用的"定时器"，让某个函数在**每个交易日**的指定时间运行。

```python
run_daily(trade, time='14:50')   # 每个交易日 14:50 运行 trade
```

- **`time` 的取值**：
  - `'open'`：开盘时（09:30）
  - `'before_open'`：开盘前
  - `'after_close'`：收盘后
  - `'14:50'` 等具体时刻
  - `'every_bar'`：每个 bar（分钟级策略用）
- 本例选 `14:50` 是因为临近收盘、当日价格基本确定，信号更稳定、不易被盘中波动干扰。
- **对比其他定时器**：`run_weekly(func, weekday, time)`（每周某天）、`run_monthly(func, monthday, time)`（每月第 monthday 个交易日），后面的选股策略会用到。

### 3.9 `attribute_history(security, count, unit, fields, df=True)` —— 取历史行情

获取**单个标的**过去 `count` 个 `unit` 周期的数据，返回 DataFrame（`df=True`）或字典（`df=False`）。

```python
closes = attribute_history('510300.XSHG', 21, '1d', 'close', df=True)['close']
# 返回一个 Series，索引是时间，值是收盘价，共 21 根日K线
```

- **参数详解**：
  - `security`：标的代码（单只股票/ETF）；
  - `count`：取多少根 K 线；
  - `unit`：周期，`'1d'`（日线）、`'1m'`（分钟线）、`'5m'` 等；
  - `fields`：字段，`'close'`、`'open'`、`'high'`、`'low'`、`'volume'`、`'money'`（成交额）等，可传列表 `['close','volume']`；
  - `df`：`True` 返回 DataFrame，`False` 返回 dict。
- **注意**：`attribute_history` 返回的**不包括当天正在进行的这根 K 线**，都是已经走完的历史数据，所以不存在"偷看未来"的问题。

### 3.10 均线计算与交叉判断（pandas 切片）

`closes` 是一个 pandas Series，`iloc` 按**位置**切片：

```python
short_ma_now  = closes.iloc[-5:] .mean()   # 最近5日收盘价均值 → 今天5日均线
short_ma_prev = closes.iloc[-6:-1].mean()  # 往前平移一天的5日均值 → 昨天5日均线
```

- `iloc[-5:]` 取最后 5 个元素，`iloc[-6:-1]` 取倒数第 6 到倒数第 2 个（左闭右开），正好是"昨天的窗口"。
- `.mean()` 是 pandas 的求均值方法。

交叉判断逻辑：

```python
# 今天短>长，且昨天短<=长，说明短均线刚刚上穿 → 金叉
if short_ma_now > long_ma_now and short_ma_prev <= long_ma_prev:
    order_target_value(security, context.portfolio.total_value * 0.95)
```

这里 `* 0.95` 是**预留 5% 现金**，避免因手续费、价格波动导致买入时现金不足而失败。

### 3.11 `order_target_value(security, value)` —— 目标市值下单

把某个标的的持仓**调整到指定市值**（元）。这是聚宽最常用的下单函数之一，因为它天然带"再平衡"能力——函数会自动计算需要买入或卖出多少股。

```python
order_target_value('510300.XSHG', 100000)  # 把持仓调整到10万元市值
order_target_value('510300.XSHG', 0)       # 市值为0 → 清仓该标的
```

**下单函数全家桶对照**（后续策略会用到）：

| 函数 | 含义 | 参数 |
|------|------|------|
| `order(security, amount)` | 按**股数**买卖（amount 正买负卖） | amount：股数 |
| `order_value(security, value)` | 按**金额**买卖 | value：金额 |
| `order_target(security, amount)` | 调整到目标**股数** | amount：目标股数 |
| `order_target_value(security, value)` | 调整到目标**市值** | value：目标市值 |
| `order_target_percent(security, pct)` | 调整到目标**仓位比例** | pct：如 0.2 = 两成仓 |

**这几个函数的共同点**：它们都是"下单"而非"立即成交"，回测中默认在下一个 bar 以开盘价撮合成交。所以它们通常返回一个 Order 对象（可查看成交状态），但初学者先记住"调仓用 target 系列最省心"即可。

### 3.12 `context.portfolio` —— 账户对象（含属性）

`context.portfolio` 是账户的资产信息，常用属性：

| 属性 | 含义 |
|------|------|
| `context.portfolio.total_value` | 总资产（现金 + 持仓市值） |
| `context.portfolio.available_cash` | 可用现金 |
| `context.portfolio.positions` | 当前持仓（字典，键为股票代码） |
| `context.portfolio.total_returns` | 累计收益率 |

本例用 `context.portfolio.total_value` 计算买入金额。

## 四、回测说明

**回测参数（建议）：**
- 回测区间：2016-01-01 ～ 2026-01-01（约 10 年）
- 初始资金：100 万元
- 频率：日频（每天 14:50 判断一次）
- 基准：沪深300（000300.XSHG）
- 手续费/滑点：已在代码中设定

**需要重点关注的指标：**
- **年化收益率**：策略平均每年的收益水平
- **最大回撤**：从峰值到谷底的最大跌幅，衡量最坏情况（趋势策略在震荡市会反复被打脸，回撤较大）
- **夏普比率**：单位风险带来的超额收益，>1 较好
- **胜率**：盈利交易次数占比（趋势策略往往胜率不高但单笔盈利大）

**如实说明**：本策略需要在聚宽平台上运行才能得到真实回测数据（本仓库不预置回测数字，避免误导）。风险提示：历史回测不代表未来，均线策略在震荡行情下会频繁产生假信号、反复止损，请勿据此实盘。

## 五、改进方向（思考题）

1. 把均线换成 EMA（指数移动平均），对近期价格赋予更高权重，能否减少滞后？
2. 加入**过滤条件**：只有当长期均线向上时才允许做多，规避熊市；
3. 把单一标的换成多标的轮动（见策略 2），分散风险。
