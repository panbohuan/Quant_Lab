## 二、心智模型：这个策略在时间轴上长什么样

先不看代码，记住三个数字：**5 天、20 天、下一根开盘。**

```
第 t-1 天收盘 ──► 算 MA5、MA20
                    │
第 t 天收盘   ──► 再算一次 MA5、MA20
                    │
                    ├─ MA5 从下方穿到 MA20 上方（金叉）
                    │        ↓
                    │   ① 用 95% 现金算"能买几手"
                    │   ② 下买单（此刻只是排队）
                    │
第 t+1 天开盘 ──► ③ 以今天的开盘价真正成交
                    │
                    └─ 之后一直持有，直到出现死叉
```

**关键的第 ③ 步**：`next()` 是在第 t 天**收盘之后**才被调用的。此时你确实看见了 t 天的收盘价，但现实中"收盘了你已经买不到了"——所以 backtrader 把成交推到 t+1 天开盘。**这不是 bug，这是它防未来函数的核心机制。**

用具体数字走一遍（编的，只看逻辑）：

| 时间 | 收盘/开盘 | MA5 | MA20 | 发生了什么 |
|---|---|---|---|---|
| 第 t-1 天 | 收 3.98 | 3.95 | 3.97 | 短均线还在长均线下方 |
| **第 t 天** | **收 4.02** | **3.99** | **3.98** | **金叉！**`cross[0] > 0`，下买单 |
| 第 t+1 天 | **开 4.05** | — | — | **以 4.05 成交**（不是 4.02） |
| 第 t+1 天 | 收 4.08 | 4.01 | 3.99 | 持仓浮盈 |
| … | … | … | … | 持有到死叉 |

> 注意：你**不会**在 `next()` 里看到 nan。因为 `SMA(period=20)` 把策略的 `minperiod` 顶到 20，引擎前 19 根根本不调用 `next()`（详见第 5.4 节）。

## 三、核心思路

**均线（Moving Average）** = 过去 N 天收盘价的算术平均：

$$MA_N = \frac{\text{最近 } N \text{ 天的收盘价之和}}{N}$$

它做的事叫**平滑**：把每天的抖动抹掉，只留下"方向"。

- **短期均线（5 日）**：只平均 5 天，反应快、紧跟价格，但也容易被噪声带偏；
- **长期均线（20 日）**：平均 20 天，更迟钝、更平滑，代表中期方向。

**两条线的交叉就是信号**：

| 信号 | 现象 | 含义 | 动作 |
|---|---|---|---|
| **金叉** | 短均线从下向上穿过长均线 | 短期价格开始强于中期趋势 | 满仓买入 |
| **死叉** | 短均线从上向下穿过长均线 | 短期走弱 | 清仓离场 |

这就是**趋势跟踪**的雏形：**不预测顶和底，只跟随已经发生的趋势**。赚的是"趋势中段"，代价是每次都要"晚半步"进场、并且会在震荡市里被反复打脸。

> **给新手的直觉**：把价格想成一列火车，均线是"火车头的平均位置"。快的车头（MA5）超过慢的车厢（MA20）→ 车在加速，上车；车头落后 → 减速，下车。你永远不知道下一站，只能跟着走。
>
> **常见误解**：很多人以为金叉"预示着要涨"。它只是"最近 5 天的平均价高于最近 20 天的平均价"这一**事实**。它涨不涨，是概率问题——这也是为什么必须回测、必须看回撤。

## 四、算法结构

```
每根日线 K 线触发 next()（不足 20 根时走 prenext，默认跳过）
   │
   ├─ 1. 指标已在 __init__ 声明：ma_fast / ma_slow / cross
   │      cross = CrossOver(ma_fast, ma_slow)  → 引擎逐根自动递推
   │
   ├─ 2. 判断 self.position（当前持仓）
   │      ├─ 空仓 且 cross[0] > 0 → 金叉 → 算整手股数 → self.buy(size=...)
   │      └─ 持仓 且 cross[0] < 0 → 死叉 → self.close()
   │
   └─ 3. 订单进入队列
          ↓
      下一根 K 线开盘价成交（默认规则，别关）
```

**为什么用 `CrossOver` 而不是自己比较今天和昨天？**
自己写要比较 4 个值（今天的 MA5/MA20、昨天的 MA5/MA20），而且很容易把"当前谁在上"和"是否发生穿越"搞混。`CrossOver` 一行搞定，且只在**发生穿越的那一根**给非零值：

```python
cross[0] > 0    # 今天发生金叉（不是"今天短均线在上"）
cross[0] < 0    # 今天发生死叉
cross[0] == 0   # 今天没发生穿越
```

要判断"现在谁在上"（状态而非事件），直接比大小：`ma_fast[0] > ma_slow[0]`。

### 5.3 策略参数与指标声明（`__init__`）

```python
class MaCross(bt.Strategy):
    params = (
        ('fast', 5),        # 短期均线周期
        ('slow', 20),       # 长期均线周期
        ('stake', 0.95),    # 买入使用的资金比例（留 5% 缓冲）
    )

    def __init__(self):
        self.ma_fast = bt.ind.SMA(self.data.close, period=self.p.fast)
        self.ma_slow = bt.ind.SMA(self.data.close, period=self.p.slow)
        self.cross = bt.ind.CrossOver(self.ma_fast, self.ma_slow)
```

**逐行说清楚三件事：**

1. `params` 是"策略参数"，用 `self.p.fast` 读。写成 params 的好处是**运行时可以覆盖**：
   `run_strategy(MaCross, data, fast=10, slow=60)`，不用改源码。
2. `__init__` 里**只声明指标，不读数值**。这三行执行时，一根 K 线都还没有——引擎只是记下"我要算 MA5、MA20、它们的交叉"。
3. `bt.ind.SMA(self.data.close, period=5)`：
   - `self.data.close` 是**数据源的一条 Line**（不是数字）；
   - 返回值也是一条 Line，所以在 `next()` 里要用 `self.ma_fast[0]` 读当前值；
   - ⚠️ **`period` 必须显式写**：`bt.ind.SMA()` 不写参数默认是 **30**，不是 20。

> **minperiod 自动生效**：`SMA(20)` 需要 20 根才有值，引擎自动把策略的 `minperiod` 设成 20（取所有指标的最大值）。**前 19 根调用 `prenext()`（默认什么都不做），第 20 根才开始调用 `next()`。** 这就是你在日志里看不到 nan 的原因。

### 5.4 主逻辑（`next()`）

```python
def next(self):
    if not self.position:                       # 空仓
        if self.cross[0] > 0:                   # 今天发生金叉
            size = round_lot(self.broker.getcash() * self.p.stake
                             / self.data.close[0])
            if size > 0:
                self.buy(size=size)
    elif self.cross[0] < 0:                     # 持仓 + 死叉
        self.close()
```

| 这一行 | 在做什么 | 为什么这么写 |
|---|---|---|
| `if not self.position:` | 判断是否空仓 | `position.size == 0` 时为假值；正数=多头、负数=空头 |
| `self.cross[0] > 0` | 读**当根**的交叉值 | `[0]`=今天。**绝不能写 `self.cross[1]`**（那是明天） |
| `self.broker.getcash()` | 用**可用现金**算股数 | 用 `getvalue()`（总资产）会连持仓市值一起算进来 |
| `* self.p.stake`（0.95） | 只投 95% 的钱 | 留 5% 缓冲：次日开盘可能高开、还要扣手续费，否则容易 `Margin` 拒单 |
| `round_lot(...)` | 向下取整到整手 | A 股 1 手 = 100 份，不能买 137 份 |
| `self.buy(size=size)` | 下买单 | **本根不成交**，下一根开盘价成交 |
| `self.close()` | 平掉全部持仓 | 等价于按持仓数量反向下单 |

> **一个容易忽略的点**：这里用 `self.data.close[0]`（今天的收盘价）估算股数，但成交价是**明天的开盘价**。如果高开，实际花的钱会更多——这就是要留 5% 的原因。

### 5.5 运行入口

## 七、与聚宽版的差异

| 维度 | 聚宽云端版 | backtrader 本地版 |
|---|---|---|
| 触发 | `run_daily(trade, time='14:50')` 盘中触发 | `next()` 每根日线自动触发（收盘后） |
| 信号 | 自己用 `attribute_history` 取 21 根算均线、比今天和昨天 | `bt.ind.CrossOver` 引擎自动递推 |
| 下单 | `order_target_value(sec, 市值)` | `self.buy(size=整手股数)` |
| 费用 | `set_order_cost(...)` | `AStockCommission`（佣金/印花税/最低 5 元） |
| 成交时点 | 平台默认 | **默认次日开盘**（本策略依赖这一点） |

**一句话**：思路完全一致，差别在"谁提供引擎"。聚宽的 `order_target_value` 自动帮你算股数并整手，backtrader 要自己算——这是 A 股整手约束带来的必然差异。

## 八、回测结果怎么读

| 指标 | 数值 | 怎么理解 |
|---|---|---|
| 累计收益率 | **+5.31%** | 13 年半只赚了 5.31% |
| 年化收益率 | **+0.39%** | 还不如货币基金 |
| 最大回撤 | **−39.24%** | 中间一度亏掉近四成——**这才是最该看的数字** |
| 夏普比率 | 0.10 | 承担了很大波动，几乎没换来收益 |
| 同期基准 | **+72.62%** | 买入持有沪深300ETF 反而赚得多 |
| 超额收益 | **−67.31%** | 大幅跑输 |

**这张成绩单说明了什么：**

1. **双均线在这段历史上是失败的**——不是代码错，是"慢牛 + 长期震荡"的 A 股宽基不适合这种纯趋势策略；
2. 震荡市里反复假金叉/假死叉 → 换手率 **23703%**（几乎每周都在动）→ 手续费和滑点持续放血；
3. 2015 年那种急跌，均线"慢半拍"来不及跑 → **−39.24% 回撤**。

> **这就是这一篇最重要的教学价值**：它教你**怎么读一份"亏钱的"回测报告**。回测不是用来找"哪个策略赚钱"，而是用来回答"如果我这样做，历史上会经历什么"。能扛住 −39% 回撤的人，才有资格谈后面的收益。

## 九、易混点与常见错误

| 症状 / 写法 | 原因 | 正确做法 |
|---|---|---|
| `self.data.close[1]` | 正索引 = **未来** | 只用 `[0]`、`[-1]`、`[-2]` |
| `__init__` 里读 `close[0]` | 此时还没有 K 线，直接报错 | 数值操作全放 `next()` |
| 第一根就写 `close[-1]` | 会**静默绕到数据集最后一行**（偷看未来） | 靠 `minperiod` 挡住，或自己判 `len(self)` |
| `bt.ind.SMA()` 不写参数 | 实际是 **30** 日均线 | 永远写 `period=` |
| 买入 137 份 | backtrader 不懂整手 | `round_lot()` |
| 满仓 `cash/price` 不留缓冲 | 次日高开 + 费用 → `order.Margin` 拒单 | 用 `stake=0.95` |
| 以为 `cross[0] > 0` 表示"短均线在上" | 它是**事件**（今天刚穿越）不是**状态** | 状态用 `ma_fast[0] > ma_slow[0]` |

## 十一、改进方向（思考题）

1. **加趋势过滤**：只在长均线向上时（`ma_slow[0] > ma_slow[-1]`）才允许买入，避开熊市里的假金叉。
2. **换参数/换指标**：试 `10/60`，或把 SMA 换成 EMA（近期权重更大）。注意：**参数在邻域内稳定才有意义**，只挑历史最优就是过拟合。
3. **加止损止盈**：用 `self.buy_bracket(...)` 一次下"主单 + 止损 + 止盈"三腿，给单笔亏损封顶，而不是被动等死叉。
4. **对比买入持有**：把 `stake` 设成 1.0 且永不卖出，直接对比"不做择时"的差距——这是判断"择时到底有没有用"的基准。
