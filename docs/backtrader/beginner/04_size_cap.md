# 策略 4：单因子小市值选股（Size / 市值因子）· backtrader 本地版

> 策略类型：单因子选股（基本面·规模因子） ｜ 难度：★★☆☆☆ ｜ 前置知识：策略 2/3（PanelStrategy/面板/因子方向）
> **运行框架：backtrader（本地回测 + 免费数据）** ｜ 本策略的**聚宽云端版**见 [docs/joinquant/beginner/04_size_cap.md](../../joinquant/beginner/04_size_cap.md)

## 一、核心思路：小市值效应

**市值（Market Cap）** 是公司在股市里的"体型"：

$$\text{总市值} = \text{股价} \times \text{总股本}$$

**小市值效应（Size Effect）** 是金融学最经典的异象之一：长期来看，**小市值股票的平均收益高于大市值股票**，A 股尤甚。解释包括：小公司更灵活、机构覆盖少导致定价低效、并购重组预期、以及 A 股历史上"壳价值"溢价等。

本策略的做法：每月按**总市值升序**（越小越靠前）选出最小的 `topn` 只，等权持有。

$$r_{\text{size}}:\ \text{排序键} = \text{total\_mv},\quad \text{取最小的 } topn \text{ 只}$$

> 给新手的直觉：菜市场里小摊贩的增长弹性往往比大超市高——小市值公司"船小好掉头"，一点点利好就能让市值翻几倍；大市值公司体量已经很大，同样利好对股价的拉动有限。但硬币的另一面是：小公司也更容易爆雷、流动性差。

**重要提示（幸存者偏差 + 数据降级）**：① 股票池用 `load_index_members('000300')` 的**当前**成分股，而沪深300成分**全是大市值公司**——这和小市值策略想要的"全市场小票"正好相反，因此本本地版的"小市值效应"会被严重**稀释**，远弱于聚宽"全市场小市值"版。要看真正的小市值效应需要全市场股票列表 + 全市场行情（数据量很大，本教学版不这么做）。② 本地免费市值源（东财）只有 **2018 年起**的日频数据，回测起点设为 `2018-01-01`。这两点都是为贴合免费源能力做的**如实降级**。

## 二、算法结构（分步拆解）

```
加载数据（main）：
   候选池 = load_index_members('000300') 前 40 只（注意：这里全是"大"票）
   逐只 load_universe(...) 取前复权日线
   data['__CAL__'] = 基准指数日线（时钟）
        │
SmallCap.__init__（一次）：
   panel = value_panel(codes, 'total_mv')   # 市值面板：index=日期, columns=代码
        │
每月调仓日 on_rebalance(cur)：
   ├─ 1. row = asof(panel, cur)        只取"不晚于 cur"的最近市值
   ├─ 2. row = row[row > 0]            剔除异常/负市值
   ├─ 3. 样本不足 topn → 本月不调仓
   └─ 4. row.sort_values() 升序取前 topn（= 市值最小）→ equal_weight_order(names, cur)
```

可见流程与策略 3 几乎一样，**唯一区别是因子列换成了 `total_mv` 且方向仍是升序**（市值越小越靠前）。这正是"因子方向"在选股策略里的关键：动量要降序、估值/市值要升序。

## 三、代码逐段详解 + backtrader 语法解析

### 3.1 引入与参数

```python
from btlab.runner import (PanelStrategy, run_strategy, load_universe,
                          value_panel, asof)

UNIVERSE_SIZE = 40
TOPN = 10
FACTOR = 'total_mv'      # 'total_mv' 总市值 / 'circ_mv' 流通市值
```

- `value_panel(codes, 'total_mv')`：拼市值面板。`total_mv` 单位为**元**（东财原始口径）。也可改 `'circ_mv'`（流通市值），逻辑完全一致。
- 其余 `PanelStrategy`、`asof`、`equal_weight_order`、`load_universe` 的用法与策略 2、3 完全相同，此处不重复展开。

### 3.2 `SmallCap(PanelStrategy)` 的 `__init__` 与 `on_rebalance`

```python
def __init__(self):
    super().__init__()
    codes = [d._name for d in self.tradables]
    self.panel = value_panel(codes, FACTOR)

def on_rebalance(self, cur):
    row = asof(self.panel, cur)
    if row is None or len(row) < self.p.topn:
        return
    row = row[row > 0]
    names = [c for c in row.sort_values().index[:self.p.topn]
             if c in self.getdatanames()]
    self.equal_weight_order(names, cur)
```

逐行解读（与前两篇重复的略）：

- `super().__init__()`：**必须先调**，否则 `self.tradables` 未生成。本例不追加新参数（沿用父类 `topn`、`rebalance`）。
- `asof(self.panel, cur)`：取调仓日及之前最近一行的市值，严格防未来函数。
- `row[row > 0]`：剔除负市值或缺失（市值<=0 的是异常/未上市情形）。
- `row.sort_values().index[:topn]`：`sort_values()` 默认**升序**，所以取到的是**市值最小**的 `topn` 只——这就是"小市值"的定义。这里和策略 3 的写法一字不差，区别只在于面板里装的是 `total_mv` 而非 `pb`。
- `if c in self.getdatanames()`：确保该代码确实加载了行情，避免 `equal_weight_order` 找不到数据源。
- `equal_weight_order(names, cur)`：等权调仓（机制见策略 2 的 3.5 节）。

### 3.3 关于因子方向的再强调

| 因子 | 含义 | 排序方向 | backtrader 写法 |
|------|------|----------|----------------|
| 动量（策略 2） | 过去涨幅 | 越大越好 | `sorted(..., reverse=True)` |
| 估值 PB（策略 3） | 越便宜越好 | 越小越好 | `row.sort_values()` 升序 |
| 市值（本策略） | 越小越好 | 越小越好 | `row.sort_values()` 升序 |

**写反方向是选股策略最常见的 bug**：把"小市值"写成降序，就会买入市值最大的蓝筹，逻辑全反。务必对照因子经济含义检查排序方向。

### 3.4 市值口径：总市值 vs 流通市值

`value_panel(codes, 'total_mv')` 取的是**总市值**（`股价 × 总股本`，单位为**元**）。本策略也支持 `'circ_mv'`（流通市值 = `股价 × 流通股本`）。两者差别在"限售股"：

- **总市值**包含大股东、战略投资者等尚未解禁的股本，反映公司整体体量；
- **流通市值**只算能在二级市场交易的部分，更贴近"实际可交易盘子的稀缺度"。

A 股历史上"小流通市值"常比"小总市值"更能捕捉壳价值与炒作弹性（可交易筹码少）。教学版默认 `total_mv` 即可，想对比 `circ_mv` 只需改 `FACTOR = 'circ_mv'`，其余代码一行不动——这正是面板因子写法的好处：**换因子只改一个字符串**。

### 3.5 因子方向对照总表（5 个入门策略）

把前 5 篇的因子方向汇总，帮你建立"因子 → 方向"的肌肉记忆：

| 策略 | 因子 | 经济含义 | 排序方向 | 写法 |
|------|------|----------|----------|------|
| 1 双均线 | 均线交叉 | 追趋势 | 上穿买/下穿卖 | `bt.ind.CrossOver` |
| 2 动量 | 过去 N 日涨幅 | 强者恒强 | 越大越好 | `sorted(..., reverse=True)` |
| 3 低估值 | PB | 越便宜越好 | 越小越好 | `row.sort_values()` 升序 |
| 4 小市值 | total_mv | 越小越好 | 越小越好 | `row.sort_values()` 升序 |
| 5 质量 | ROE | 越赚钱越好 | 越大越好 | `row.sort_values(ascending=False)` |

> 漏看这张表，最容易把本策略写成 `ascending=False`（选出市值最大的银行/石油），完全背离"小市值"初衷。

### 3.6 一个具体排序示例（看清升序取最小）

假设某调仓日 `asof` 返回（已剔除 `<=0` 后）几只票的市值（示意，单位元）：

```
002142: 1.2e11    600000: 1.8e11    300750: 8.0e11    600519: 2.1e12
```

`row.sort_values()` 升序得到 `[002142, 600000, 300750, 600519]`；取 `topn=10` 在本例里就取最小的几只。`sort_values` 默认升序，所以**不需要写任何参数**就是"市值最小在前"——写反只需多打 `ascending=False` 一个词，危害极大。

### 3.7 小市值因子的 A 股特征与政策风险

理解因子背后的制度背景，才能正确解读回测：

- **壳价值溢价**：A 股很长一段时间上市难（核准制 + 排队），"上市公司的壳"本身值钱，小市值公司被炒"借壳"预期，这是小市值效应在 A 股尤其强的重要制度原因。
- **2016 年前后拐点**：随着注册制推进、退市常态化，壳价值快速贬值，小市值效应的强度和稳定性明显下降；2020 年后的"核心资产"行情更是让小票长期跑输。
- **流动性风险**：小市值票成交薄，单笔稍大就可能推不动，实盘里 `equal_weight_order` 的整手换算可能因成交量不足难以按理想价成交。

所以回测里 689.93% 的亮眼数字，**不可直接外推到未来**——它既含幸存者偏差，也含一段特定制度红利期的历史收益。

### 3.8 常见写错与陷阱

| 写法 | 后果 | 正确做法 |
|------|------|----------|
| 排序方向误用降序 | 买入市值最大的蓝筹，背离"小市值" | `row.sort_values()` 升序（默认） |
| 不剔 `row[row>0]` | 异常/负市值票入选 | 先过滤再排序 |
| 期待复现聚宽"全市场小市值" | 本地池是沪深300成分，效应被稀释 | 认清数据降级（见第一节提示） |
| 子类漏 `super().__init__()` | `self.tradables` 不存在 | 第一行调 `super().__init__()` |
| 误以为市值是"亿元" | 单位误判（实际是元） | 排序只看相对大小，单位不影响结果 |

### 3.9 本策略的绩效从哪来（与策略 1 同源）

本策略不自己算绩效——`run_strategy` 用 `NavRecorder`（逐日账户总值）得到净值序列，再用 `bt.analyzers.Transactions` 汇总成交笔数与累计成交额。日志里的"累计换手率 7357.39%" =（所有成交金额之和）/ 初始资金 100 万。月频换 10 只、每只平均持有约 1 个月，高换手是这类选股策略的固有特征，也是它实际摩擦成本的来源。

### 3.10 想跑"真实全市场小市值"要准备什么

本地版把池子限制在前 40 只沪深300成分，是算力与免费源妥协的结果。要复现聚宽"全市场小市值"的强度，需要：

1. 一份**全市场股票列表**（含已退市，否则仍有幸存者偏差）；
2. 全市场**日线行情**（几千只 × 十几年，数据量与拉取时间都大很多）；
3. 在 `main()` 里把 `load_index_members` 换成全市场列表，并把 `load_universe` 的 `codes` 换掉即可——`PanelStrategy` / `equal_weight_order` / `asof` 全部复用，无需改策略核心。

这也体现了本仓库"策略与数据解耦"的设计：`SmallCap` 类只关心"市值升序选最小"，至于股票池从哪来，由 `main()` 决定。把数据和逻辑绑死（像某些脚本把股票列表硬编码进策略类）会让你换池子时被迫重写策略，本仓库刻意避免了这点。

### 3.11 circ_mv 与 total_mv 的实盘差异提醒

虽然在排序方向上两者一致（升序取小），但流通市值更小的票往往**流动性更差、被炒作概率更高**。如果你把 `FACTOR` 改成 `'circ_mv'` 发现收益更高，要先问自己：这部分超额是不是来自"更小的可交易盘子更容易被游资拉抬"——它对应的是更高的流动性风险，而不是公司基本面的便宜。回测数字变好不等于实盘可复制，这是读因子结果时务必保持的清醒。

## 四、与聚宽版的差异

| 维度 | 聚宽版（云端） | backtrader 本地版 |
|------|----------------|-------------------|
| 股票池 | `get_all_securities(['stock'])` **全市场** | `load_index_members('000300')` **当前**成分（全是大票，效应被稀释） |
| 取市值 | `query(valuation.market_cap).order_by(market_cap.asc())` | `value_panel(codes,'total_mv')` + `asof` |
| 数据时点 | 任意历史时点 | 仅 2018 年起（区间缩短，降级） |
| 排序方向 | `market_cap.asc()` 升序 | `row.sort_values()` 升序（一致） |
| 过滤 | `filter_stocks` 六道过滤 | 仅 `live()` 跳过停牌 |
| 下单 | `order_target_value` | `equal_weight_order` 整手股数 |

思路（市值升序选小票）完全一致。核心差异是**股票池被限定在沪深300成分**，使得本地版无法复现聚宽"全市场小市值"的强效应——这是数据源与算力限制下的诚实降级，不是策略逻辑改动。若想真正验证小市值因子，需要在本地接入全市场行情（数据量与拉取时间都会大很多）。

## 五、回测结果（真实数据）

回测区间 **2018-01-02 ~ 2026-09-30**（2123 个交易日），初始资金 100 万元，沪深300成分股前 40 只、月频调仓、总市值升序选前 10 只，基准沪深300指数：

| 指标 | 数值 |
|------|------|
| 累计收益率 | 689.93% |
| 年化收益率 | 27.80% |
| 最大回撤 | -29.58% |
| 夏普比率 | 1.19 |
| 基准累计收益率 | 6.61% |
| 超额收益 | 683.32% |
| 总成交笔数 | 1058 |
| 累计换手率 | 7357.39% |

**解读（仅基于上表真实数字）：** 即便股票池被限制在"大票为主"的沪深300成分里，市值最小的 10 只依然录得惊人的 689.93% 累计、27.80% 年化，夏普高达 1.19、回撤仅 -29.58%——这强有力地印证了"小市值因子有效"的常识。但请注意：① 这 40 只成分里市值最小的，在全市场视角下其实仍是中大盘，若换成**真实全市场小票**，聚宽版的收益会更高、波动也更极端，本地的数字反而"保守"了；② 同样存在**幸存者偏差**（当前成分）；③ 小市值因子对流动性和"壳价值"政策高度敏感，2016 年之前的 A 股小票效应远比现在强，且受监管政策影响大，回测亮眼不等于未来可复制。

## 六、改进方向（思考题）

1. **换真实全市场股票池**：接入全市场行情与列表（btlab 可扩展），才能真正复现小市值因子的完整强度与风险，而不是"成分股里挑小的"。
2. **小市值 + 低估值复合**：小市值里再叠加 PB/PE 过滤（结合策略 3），剔除"小但贵/小但烂"的票，做"小而便宜"的双因子。
3. **加流动性与止损约束**：小票流动性差，`equal_weight_order` 的整手换算可能因成交量不足难以成交；可加 `buy_bracket` 止损、或用成交量过滤，避免在停牌/跌停股上卡单；也可对比 `'circ_mv'`（流通市值）看口径差异。
