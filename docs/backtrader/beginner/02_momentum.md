## 一、这一篇你将学到什么

这是**从"单标的择时"跨到"多标的选股"的第一篇**，也是整本书里最重要的转折点。

| 你会搞懂 | 一句话 |
|---|---|
| `PanelStrategy` 骨架 | 选股类策略只需要写"选谁"，调度和下单交给基类 |
| `__CAL__` 日历源 | 为什么多标的回测必须有一个"每天都有行情"的时钟 |
| `live(d, cur)` | 怎么判断"这只票今天能不能交易" |
| `hist_close(d, n)` | 怎么取"最近 n 根收盘价"（注意它是 array，不是 Line） |
| `equal_weight_order()` | 怎么把组合调成"等权"，以及为什么必须"先卖后买 + 整手" |
| **序列语义 vs Line 语义** | 本仓库最容易搞混的一对概念（详见 5.4） |

**读完你应该能回答**：为什么一个"选股"策略里，`next()` 被分成了"调度"和"选股"两层？

## 二、心智模型：这个策略在时间轴上长什么样

参数：**回看 60 个交易日、持有 10 只、每月调仓一次。**

```
每月第一个交易日（收盘后）
   │
   ├─ 1. 对股票池里每一只还在交易的股票：
   │        取它最近 61 根收盘价 → 涨跌幅 = 最后一天 / 第一天 - 1
   │        （用 61 根是为了算"60 个交易日的涨幅"）
   │
   ├─ 2. 按涨跌幅从大到小排序，取前 10 名
   │
   ├─ 3. 先卖出：不在前 10 名的持仓
   │
   ├─ 4. 再买入：把前 10 名每只调到"总资产的 9.8%"（0.98 ÷ 10）
   │        · 股数向下取整到 100 股
   │        · 已经持有的只补差额
   │
   └─ 5. 成交：发生在"下一个交易日开盘"
```

**用具体数字走一遍**（编的，只看逻辑）：

| 股票 | 过去 60 日涨幅 | 排名 | 动作 |
|---|---|---|---|
| A | +32% | 1 | 买入（调到 9.8% 仓位） |
| B | +21% | 2 | 持有/微调 |
| C | +5% | 6 | 持有 |
| … | … | … | … |
| K | −18% | 第 11 名 | **卖出** |
| L | −25% | 第 12 名 | **卖出** |

> 注意"每月调仓"不是"每月第一天买入"：**信号在当天收盘后算出，真正成交在下一个交易日开盘**（backtrader 默认规则）。

## 三、核心思路

**动量效应（Momentum）**：过去一段时间涨得好的股票，未来一段时间**倾向于**继续跑赢。

**为什么会存在？**（这不是玄学，有三种常见解释）

1. **信息扩散慢**：好消息不是一天被所有人消化，资金分批进场；
2. **行为偏差**：投资者倾向"追涨"，形成正反馈；
3. **机构调仓**：指数成分股调整、基金申赎会带来持续性买盘。

**公式**（本策略用的就是它）：

$$Momentum = \frac{P_t}{P_{t-60}} - 1$$

即"最近 60 个交易日的累计涨跌幅"。

**一个必须知道的对照**：动量（追涨）和反转（抄底）是**方向相反**的两类策略，但它们在 A 股可以**同时成立**——只是时间尺度不同：

| 时间尺度 | 常见现象 | 对应策略 |
|---|---|---|
| 1～5 个交易日 | 短期反转（超跌反弹） | `bt_a09` |
| 1～6 个月 | 中期动量（强者恒强） | **本策略** |

> **常见误解**：动量策略不是"买涨得最多的"，而是"买**过去**涨得多的"。**过去不代表未来**——动量因子最怕的是**动量崩溃**：一旦风格切换，前期涨得最多的股票往往跌得最狠。这正是本策略回撤高达 −49.75% 的原因。

## 四、算法结构

```
run_strategy() 启动
   │
   ├─ data = load_universe(40 只沪深300成分股)   ← 每只一个 DataFrame
   ├─ data['__CAL__'] = 沪深300指数日线           ← 当天有行情的"时钟"
   │
   └─ 每根 K 线 → PanelStrategy.next()
         │
         ├─ 用 __CAL__ 的日期算 (年, 月)
         │     └─ 和上次相同？→ 直接 return（这就是"每月调仓一次"）
         │
         └─ 变了？→ 调用 on_rebalance(cur)
               ├─ 遍历 tradables（排除 __CAL__）
               ├─ live(d, cur)？停牌/未上市 → 跳过
               ├─ hist_close(d, 61) → 算 60 日涨幅
               ├─ 有效样本 < 10 只 → 本月不调仓
               └─ 排序取前 10 → equal_weight_order()
                     ├─ 先卖不在名单里的
                     ├─ 再把名单内每只调到 9.8% 仓位（整手）
                     └─ 次日开盘成交
```

## 五、代码逐段详解

> 文件：`strategies/backtrader/beginner/bt_s02_momentum.py`

### 5.1 参数区

```python
START = '2015-01-01'
END = None
CASH = 1_000_000
BENCHMARK = '000300'
UNIVERSE_SIZE = 40          # 股票池大小（取沪深300前 40 只，控制拉数据时间）
LOOKBACK = 60               # 动量回看期（交易日）
TOPN = 10                   # 持仓只数
REBALANCE = 'monthly'       # 调仓频率：daily / weekly / monthly
```

| 参数 | 改了会怎样 |
|---|---|
| `UNIVERSE_SIZE` | 40 → 300：样本更全，但首次拉数据从 1 分钟变成十几分钟 |
| `LOOKBACK` | 60 → 20：更敏感、换手更高；→ 120：更稳、更迟钝 |
| `TOPN` | 10 → 5：更集中、波动更大 |
| `REBALANCE` | 改成 `'weekly'` 会显著提高换手和成本 |

### 5.2 策略类：只写"选谁"

```python
class Momentum(PanelStrategy):
    params = (
        ('lookback', LOOKBACK),
        ('topn', TOPN),
        ('rebalance', REBALANCE),      # 骨架用它决定调度频率
    )

    def on_rebalance(self, cur):
        scores = {}
        for d in self.tradables:                      # 遍历所有可交易标的
            if not self.live(d, cur):                 # 停牌/未上市 → 跳过
                continue
            closes = self.hist_close(d, self.p.lookback + 1)
            if closes is None or closes[0] <= 0:      # 数据不足或异常价格
                continue
            scores[d._name] = closes[-1] / closes[0] - 1.0   # 区间收益率
        if len(scores) < self.p.topn:                 # 有效样本不足
            return
        target = sorted(scores, key=scores.get, reverse=True)[:self.p.topn]
        self.equal_weight_order(target, cur)          # 交给基类去调仓
```

**逐行拆解：**

| 代码 | 在做什么 | 为什么这么写 |
|---|---|---|
| `self.tradables` | 基类帮你去掉 `__CAL__` 后的标的列表 | 日历不是交易标的 |
| `self.live(d, cur)` | "它今天有行情吗？" | 停牌期间它的日期停在旧日期，用它交易=用旧价成交（假成交） |
| `self.hist_close(d, lookback+1)` | 取最近 61 根收盘 | 要算 60 日涨幅，需要 61 个价格点 |
| `if closes is None` | `hist_close` 在不足 n 根时返回 None | **这就是防未来函数的第一道闸门** |
| `closes[0] <= 0` | 防御异常/负价格（前复权极端情况） | 除法分母保护 |
| `closes[-1] / closes[0] - 1` | 60 日涨幅 | 见 5.3 的"序列语义"警告 |
| `len(scores) < topn` | 有效样本不够就**不调仓** | 不能"硬凑 10 只" |
| `sorted(..., reverse=True)[:topn]` | 取涨得最多的前 10 | 动量方向：越大越好 |
| `self.equal_weight_order(target, cur)` | 等权调仓 | 基类负责先卖后买、整手、留缓冲 |

### 5.3 ⚠️ 最容易搞混的：`closes[-1]` 到底是哪天？

这是本仓库反复强调的**一对相反语义**：

| 写法 | 类型 | `[0]` | `[-1]` |
|---|---|---|---|
| `d.close[0]` / `d.close[-1]` | backtrader **Line** | **今天** | **昨天** |
| `closes = d.close.get(size=61)` | **array**（数组） | **最旧**（61 天前） | **最新**（今天） |

所以：

```python
closes[-1] / closes[0] - 1      # ✅ 最新 / 最旧 - 1 = 60 日涨幅
closes[0] / closes[-1] - 1      # ❌ 写反了，会得到"过去 60 天跌了多少"
```

> **为什么容易搞混**：`get()` 返回的是一个**按时间从旧到新排列的数组**——它的 `[-1]` 是"最后一个元素=最新"，而 Line 的 `[-1]` 是"往回一格=昨天"。一个是"序列取末尾"，一个是"时间往回退"，方向正好相反。
>
> 另外：`get(size=n)` 返回的是 **`array.array`，不是 Python list**（虽然索引、切片、`sum()` 都能用）。

### 5.4 主函数：为什么要 `__CAL__`

```python
def main():
    codes = load_index_members('000300')[:UNIVERSE_SIZE]
    data = load_universe(codes, start=START, end=END, adjust='qfq', label='股票池')
    data['__CAL__'] = load_daily(BENCHMARK, start=START, end=END)   # ← 日历源
    run_strategy(Momentum, data, cash=CASH, benchmark=BENCHMARK)
```

| 步骤 | 作用 |
|---|---|
| `load_index_members('000300')` | 取沪深300成分股。⚠️ **只有当前成分股**（幸存者偏差的来源） |
| `[:UNIVERSE_SIZE]` | 只取前 40 只，目的是让拉数据快一些 |
| `load_universe(...)` | 批量取日线；**自动剔除上市太晚的标的**（日志里会打印"候选 40 → 数据可用 38"） |
| `data['__CAL__']` | 喂一条"每个交易日都有行情"的指数，当**时钟** |

**为什么需要 `__CAL__`？** backtrader 是以**主数据源**（第一个 `adddata` 的）的 K 线数为节拍推进的。如果某只股票停牌，它的数据线就停在那里——你就无法判断"今天是几号"。用一个每天都有数据的指数当节拍器，`next()` 才会在每个交易日准时触发。

## 六、一次真实运行的轨迹

```
[1/3] 获取沪深300成分股（前 40 只）...
[2/3] 加载 40 只股票日线（前复权）...
  已加载 20/40 ...
  已加载 40/40 ...
[btlab] 股票池：候选 40 只 → 数据可用 38 只
[3/3] 开始 backtrader 回测 ...
```

每个月调仓时，`equal_weight_order` 会产生这样一批订单（示意）：

```
2015-02-03 卖出 000651 -1200 股 @ 41.20     ← 跌出前 10 名
2015-02-03 买入 601318  +800 股 @ 68.50     ← 新进前 10 名
2015-02-03 买入 000002  +300 股 @ 15.30     ← 补齐差额
```

**注意日期**：信号在 2 月 3 日（当月第一个交易日）**收盘后**算出，订单在 **2 月 4 日开盘**成交——日志里的日期是成交日。

## 七、与聚宽版的差异

| 维度 | 聚宽 | backtrader 本地版 |
|---|---|---|
| 股票池 | `get_index_stocks('000300.XSHG')` — **当时的历史成分股** | `load_index_members()` — 只有**当前**成分股（幸存者偏差） |
| 取历史行情 | `attribute_history(s, 61, '1d', 'close')` | `self.hist_close(d, 61)`（内部是 `d.close.get(size=61)`） |
| 定时调仓 | `run_monthly(rebalance, 1)` | `PanelStrategy` 的 `(年, 月)` 变化检测 |
| 目标仓位 | `order_target_value(s, 总资产/10)` | `equal_weight_order()`（自己算整手股数） |
| 停牌处理 | 平台自动拒单 | 自己用 `self.live(d, cur)` 判断 |

**一句话**：聚宽把"历史成分股、定时器、整手、停牌"都藏在平台里；backtrader 是库，这些必须自己写。**这也是为什么本地版要诚实地标注"幸存者偏差"**。

## 八、回测结果怎么读

区间 2015-01 ~ 2026-09，初始 100 万，基准沪深300：

| 指标 | 数值 | 怎么理解 |
|---|---|---|
| 累计收益率 | **+165.02%** | 看起来不错 |
| 年化收益率 | **+8.98%** | 比基准（+19.66% 累计）明显更好 |
| 最大回撤 | **−49.75%** | ⚠️ **接近腰斩**，这是它真正的代价 |
| 夏普比率 | 0.45 | 收益尚可，但波动很大 |
| 成交笔数 | 1723 | 11 年多，平均每 2 个月换一遍仓 |

**三个必须同时读出的结论：**

1. **收益确实跑赢基准**（+165% vs +19.66%），说明动量在 A 股这段历史里有超额；
2. **但回撤 −49.75%**：中期动量崩溃（如 2015 股灾、2021 风格切换）时，前期涨最多的一批股票集中下跌；
3. **⚠️ 收益被高估了**：股票池是"当前"沪深300成分股，而它们本来就是"活到今天并且进了指数"的公司——**幸存者偏差**。真实的、用当时成分股的回测会更差。

> **一句话**：+165% 这个数字**不能直接引用**。它是"教学读数"，用来理解动量因子的形状（收益高、回撤大），不是实盘预期。

## 九、易混点与常见错误

| 症状 | 原因 | 正确做法 |
|---|---|---|
| 涨幅算反了 | 把 `closes[0]` 当最新 | 记住：**array 的 `[0]` 最旧、`[-1]` 最新** |
| 报错 `array + list` | 以为 `get()` 返回 list | 它是 `array.array`；要 list 就 `list(...)` |
| 某只票用停牌前的价格成交了 | 没判 `live()` | 每轮先 `if not self.live(d, cur): continue` |
| 调仓次数远超预期 | `next()` 每根都触发 | 靠 `PanelStrategy` 的 `(年,月)` key 去重；自己写要记得去重 |
| 只有 3 只股票也照样买 | 没判"有效样本 < topn" | 样本不足就 `return`，不调仓 |
| 收益虚高 | 用了当前成分股 | 明白这是幸存者偏差；有条件时换成历史成分股 |

## 十一、改进方向（思考题）

1. **风险调整动量**：把"涨幅"换成"涨幅 ÷ 波动率"，避免选到"涨得多但极不稳"的股票。
2. **加趋势过滤**：只在指数在长期均线上方时才选股，熊市空仓。
3. **去幸存者偏差**：改用历史上真实存在过的成分股列表（聚宽版已做到），观察收益下降多少——**这个对比本身就是最好的一课**。
4. **换调仓频率**：把 `REBALANCE` 改成 `'weekly'`，观察收益与换手率的变化，理解"成本 vs 及时性"的权衡。
