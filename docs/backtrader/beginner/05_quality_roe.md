## 一、核心思路：质量投资与 ROE

如果说策略 3 买"便宜的"、策略 4 买"小的"，策略 5 买的是"**好的**"——盈利能力强的优质公司。

### 1.1 净资产收益率 ROE

$$ROE = \frac{\text{净利润}}{\text{净资产（股东权益）}}$$

含义：股东每投入 1 元净资产，公司一年能赚多少钱。ROE=15% 意味着每 100 元股东资本创造 15 元利润。ROE 是衡量公司**赚钱效率**最综合的指标，长期高 ROE 往往意味着公司拥有护城河（品牌、技术、成本、网络效应），能持续创造超额利润。

### 1.2 杜邦分析：ROE 的三个来源

$$ROE = \underbrace{\frac{净利润}{营收}}_{净利率} \times \underbrace{\frac{营收}{总资产}}_{周转率} \times \underbrace{\frac{总资产}{净资产}}_{杠杆}$$

- **高净利率**（茅台式）：盈利质量高，最优；
- **高周转**（沃尔玛式）：经营效率高，次优；
- **高杠杆**（银行式）：靠借钱放大收益，ROE 虚高、风险高。

> 所以同样是 ROE=20%，靠高杠杆堆出来的"含金量"远不如靠高净利率。进阶策略会同时看 ROE 与资产负债率。

本策略固定按 **ROE 降序**取最高的 `topn` 只，等权持有：

$$r_{\text{quality}}:\ \text{排序键} = ROE,\quad \text{取最大的 } topn \text{ 只}$$

> 给新手的直觉：买股票就是当公司的"合伙人"。你当然想挑那个"每投 100 块每年能稳定赚 15 块以上"的靠谱生意，而不是一年到头不赚钱的。ROE 就是帮你快速筛出"好生意"的尺子。

**重要提示（幸存者偏差 + 数据降级）**：① 股票池仍是 `load_index_members('000300')` 的**当前**成分股（幸存者偏差，收益偏高）；② 本地 ROE 来自新浪季度财务数据，只有**报告期**没有**公告日**，本策略用 `roe_panel(..., lag_days=45)` 把报告期后移 45 天近似公告延迟（见第三节），这是防未来函数的关键处理，但仍是教学简化；③ 回测起点设为 `2018-01-01`（财务数据覆盖能力）。

## 二、算法结构（分步拆解）

```
加载数据（main）：
   候选池 = load_index_members('000300') 前 40 只
   逐只 load_universe(...) 取前复权日线
   data['__CAL__'] = 基准指数日线（时钟）
        │
QualityROE.__init__（一次）：
   panel = roe_panel(codes, lag_days=45)   # ROE 面板：报告期 +45 天 = 可用日
        │
每月调仓日 on_rebalance(cur)：
   ├─ 1. row = asof(panel, cur)   只取"不晚于 cur"的最近一期 ROE（滞后后）
   ├─ 2. 样本不足 topn → 本月不调仓
   ├─ 3. row.sort_values(ascending=False) 降序取前 topn（= ROE 最高）
   └─ 4. equal_weight_order(names, cur)
```

与策略 3/4 的区别：因子换成 ROE、方向为**降序**（越大越好），且底层用 `roe_panel` 而非 `value_panel`。

## 三、代码逐段详解 + backtrader 语法解析

### 3.1 引入与参数

```python
from btlab.runner import (PanelStrategy, run_strategy, load_universe,
                          roe_panel, asof)

UNIVERSE_SIZE = 40
TOPN = 10
LAG_DAYS = 45        # 报告期 → 可用日 的滞后天数（近似公告延迟）
```

### 3.2 `roe_panel(codes, lag_days=45)` —— 季度数据的"公告滞后"处理（本策略重点）

```python
def roe_panel(codes, lag_days=45, verbose=True):
    s = roe_series(c)                 # 新浪季度 ROE 序列（index=报告期）
    s.index = s.index + pd.Timedelta(days=lag_days)   # 报告期后移 45 天
    ...
```

这是本策略**最关键、也最容易写错**的一步：

- 财报是**按季度披露**的。例如 2024 年年报的报告期是 `2024-12-31`，但它实际要到 **2025 年 4 月**才公告。如果回测在 `2024-12-31` 就用了这份 ROE，等于"报告期当天就知道结果"——典型的**未来函数**。
- `roe_panel` 把每份报告期的索引**后移 `lag_days`（默认 45 天）**，把"报告期"近似成"可知道的日子"。这样 `asof(panel, cur)` 在 2025 年 4 月之前取不到这份年报，从 4 月之后才能用到——符合"公告之后才知情"的真实约束。
- 这是教学简化（真实公告日可在聚宽查到精确值），但方向正确：**宁可滞后、不可超前**。

### 3.3 `QualityROE(PanelStrategy)` 的 `__init__` 与 `on_rebalance`

```python
def __init__(self):
    super().__init__()
    codes = [d._name for d in self.tradables]
    self.panel = roe_panel(codes, lag_days=LAG_DAYS)

def on_rebalance(self, cur):
    row = asof(self.panel, cur)
    if row is None or len(row) < self.p.topn:
        return
    names = [c for c in row.sort_values(ascending=False).index[:self.p.topn]
             if c in self.getdatanames()]
    top_roe = row.sort_values(ascending=False).iloc[0] if len(row) else float('nan')
    print(f'  [{cur}] ROE 最高 {top_roe:.2f}%')
    self.equal_weight_order(names, cur)
```

逐行解读：

- `super().__init__()`：必须先调，生成 `self.tradables`。
- `roe_panel(codes, lag_days=LAG_DAYS)`：预加载带"公告滞后"的 ROE 面板（季度数据，月内保持不变，`asof` 取最近一期）。
- `asof(self.panel, cur)`：取"不晚于 cur"的最近一期 ROE（已滞后，防未来函数）。面板为空或 `cur` 早于所有数据则 `None`。
- `row.sort_values(ascending=False)`：**降序**（大→小），取 `[:topn]` 即 ROE 最高的 `topn` 只。这里方向和策略 3/4 的升序相反，是"质量因子越大越好"的经济含义决定的。
- `if c in self.getdatanames()`：确保代码已加载行情。
- `top_roe = ...iloc[0]` 与 `print(...)`：日志输出本月选中股票里的最高 ROE（回测日志里那一长串 `[2018-01-02] ROE 最高 47.21%` 就来自这里），方便观察选股质量；对交易逻辑无影响。
- `equal_weight_order(names, cur)`：等权调仓（机制见策略 2 的 3.5 节）。

### 3.4 季度数据 vs 日频价格的衔接

ROE 是**季度阶梯式**变化（一个季度内数值不变），而股价是**日频连续**变化。两者通过各自的日期索引自然对齐：`asof` 在每个月调仓日取"最近已公告"的那一期 ROE，复权价则取当根 `d.close[0]`，互不影响。这就是为什么面板 + `asof` 是处理低频基本面因子最干净的方式。

### 3.5 相关质量指标与 DuPont 扩展（不止 ROE）

ROE 是唯一指标时容易踩坑（高杠杆虚高）。btlab 的 `value_panel` / `load_financial_indicator` 还能取这些质量相关字段，进阶时很有用：

| 指标 | 含义 | 方向 | 说明 |
|------|------|------|------|
| `roe` | 净资产收益率 | 越高越好 | 本策略核心指标 |
| `roa` | 总资产收益率 | 越高越好 | 不含杠杆，比 ROE 更"纯" |
| `gross_profit_margin` | 毛利率 | 越高越好 | 反映定价权/竞争壁垒 |
| `inc_net_profit_year_on_year` | 净利润同比增速 | 越高越好 | 成长性 |

> DuPont 拆解（见第一节）告诉我们：同样是 ROE=20%，靠高净利率（茅台式）远优于靠高杠杆（银行式）。进阶做法可加 `roa` 与资产负债率过滤，剔除"伪高质量"——这也是策略 7 多因子会做的事。

### 3.6 公告滞后的取舍（lag_days 不是越大越好）

`roe_panel` 用 `lag_days=45` 把报告期后移，模拟"季报在报告期后约 1~1.5 个月才公告"：

- **太小（如 0）**：等于报告期当天就用，明显未来函数；
- **太大（如 120）**：虽更"安全"，但财务数据本就季度更新，过长滞后让策略长期用着过时 ROE，变相降低因子频率；
- **45 天**是 A 股年报/季报从期末到公告常见间隔的经验值，属教学近似。真实公告日可在聚宽按 `statDate` + 公告日精确对齐。

### 3.7 常见写错与陷阱

| 写法 | 后果 | 正确做法 |
|------|------|----------|
| 排序方向误用升序 | 买入 ROE 最低的烂公司 | `row.sort_values(ascending=False)` 降序 |
| 不用 `lag_days` 直接用报告期 | 未来函数（期末已知未公告的 ROE） | `roe_panel(..., lag_days=45)` |
| 不处理缺失 ROE | NaN 进入排序、选出无效代码 | `asof` 已 `dropna`；必要时再过滤 |
| 单看 ROE 忽略杠杆 | 选中高杠杆"伪优质" | 进阶叠加 `roa`/`资产负债率` 过滤 |
| 子类漏 `super().__init__()` | `self.tradables` 不存在 | 第一行调 `super().__init__()` |

### 3.8 本策略绩效从哪来（与策略 1 同源）

本策略同样不自己算绩效——`run_strategy` 用 `NavRecorder`（逐日账户总值）得到净值序列，再用 `bt.analyzers.Transactions` 汇总成交笔数与累计成交额。日志里那一长串 `[2018-01-02] ROE 最高 47.21%` 来自 `on_rebalance` 里的 `print`，对交易逻辑无影响，仅方便你观察每个月选中股票的质量水平与 ROE 的阶梯式变化。

### 3.9 季度财务数据的其他坑

除了公告滞后，季度 ROE 还有两个常见坑：

- **缺失报告期**：某公司某年未披露（如 ST、审计问题），`roe_series` 会有空洞，`roe_panel` 拼面板时该列出现 NaN；`asof` 的 `dropna` 会自动跳过这些点，但当季该票可能因无 ROE 落选——这是合理行为，不是 bug。
- **一次性损益扭曲**：卖资产、政府补助会让单季 ROE 暴增，`asof` 取到这一期会把"伪优质"选入。进阶可要求"近 N 年 ROE 均值"而非单期（见第六节的改进方向 2）。

这些坑聚宽版同样存在，区别只在于本地源只能给报告期、要靠 `lag_days` 近似公告日；聚宽能用 `statDate` + 精确公告日对齐，未来函数控制更严。无论哪个框架，**财务数据永远比价格数据"慢半拍"**，做基本面量化时这是第一条要刻进肌肉记忆的约束。

### 3.10 为什么单因子 ROE 收益不如估值/市值

对照本系列回测：策略 3（低估值）累计 136.91%、策略 4（小市值）689.93%，而本策略（高 ROE）仅 62.27%。原因有两层：① 高 ROE 公司大多已被市场充分定价（茅台、宁德这类"好公司"不便宜），估值前置消化了质量溢价，单因子 ROE 的额外 Alpha 有限；② ROE 是"结果型"指标，滞后于基本面变化，而估值/市值带更多"预期差"和"小票弹性"。这正说明：质量因子更适合**做多因子里的"压舱石"**（与估值结合挑"便宜的好公司"），而非单独裸跑——这也是策略 7 多因子要走的路。

### 3.11 与策略 3/4 的衔接

质量因子和估值、市值因子是"价值投资三件套"：估值回答"贵不贵"、市值回答"盘子大不大"、质量回答"好不好"。三者可两两组合或三者合一构成多因子（策略 7）。读这 5 篇时建议按"技术（1）→ 量价（2）→ 估值（3）→ 规模（4）→ 质量（5）"的顺序，逐步从单标的过渡到多标的、从价格因子过渡到基本面因子，每篇都用到的 `PanelStrategy` / `asof` / `equal_weight_order` 也会越用越熟。

## 四、与聚宽版的差异

| 维度 | 聚宽版（云端） | backtrader 本地版 |
|------|----------------|-------------------|
| 取 ROE | `query(indicator.roe).order_by(indicator.roe.desc())` + `get_fundamentals` | `roe_panel(codes, lag_days=45)` + `asof` |
| 数据时标 | 平台按**公告日**对齐的历史财务 | 只有**报告期**，用 +45 天近似公告滞后（教学简化） |
| 股票池 | `get_all_securities(['stock'])` 全市场 | `load_index_members('000300')` 当前成分（幸存者偏差） |
| 排序方向 | `roe.desc()` 降序 | `row.sort_values(ascending=False)` 降序（一致） |
| 数据时点 | 任意历史时点 | 仅 2018 年起（区间缩短，降级） |
| 过滤 | `filter_stocks` 六道过滤 | 仅 `live()` 跳过停牌 |
| 下单 | `order_target_value` | `equal_weight_order` 整手股数 |

思路（高 ROE 降序选股）完全一致。最核心的差异是**财务数据的"公告滞后"**：聚宽云端用平台整理好的公告日对齐数据，本地免费源只有报告期，所以本策略必须显式 `lag_days` 后移来防未来函数——这是本地版独有的、必须讲清楚的细节。

## 六、改进方向（思考题）

1. **质量 + 估值结合**：这正是价值投资精髓——"便宜的好公司"。把策略 3 的 PB 与策略 5 的 ROE 合成综合分（如 ROE 降序、PB 升序各取前 N 取交集或打分），可同时受益于两个因子、平滑回撤。
2. **用连续多年 ROE 而非单期**：单季 ROE 可能受一次性损益扭曲，进阶做法要求"近 3 年 ROE 均 > 15%"，选出真正稳定的优质公司（可在 `roe_panel` 基础上按代码做滚动筛选）。
3. **剔除高杠杆伪质量 + 加止损**：ROE 高但资产负债率也高的公司"含金量"低，应降权；同时用 `buy_bracket` 止损把 -42.18% 这种回撤压下来；也可对比 `roa`（剔除杠杆因素，更"纯"的质量指标）。
