## 一、这一篇你将学到什么

这一篇引入了一个前四篇都没有的新问题：**财报是"季度公布"的，但它描述的是"过去某个报告期"的经营情况。** 你什么时候才能用这份财报？

| 你会搞懂 | 一句话 |
|---|---|
| ROE 的含义 | 每 1 元净资产能赚回多少利润 |
| `roe_panel(codes, lag_days=45)` | 把财报索引整体后移 45 天，**模拟公告延迟** |
| 为什么必须滞后 | 报告期 ≠ 公告日，用报告期就是未来函数 |
| 季度数据的"阶梯状" | ROE 一年只有 4 个新值，其余时间保持不变 |

**读完你应该能回答**：2020-03-31 的一季报，为什么不能从 2020-04-01 就开始用？

---

## 二、心智模型：这个策略在时间轴上长什么样

```
报告期（3/31、6/30、9/30、12/31）
      │
      │  公司实际公告往往滞后 1～1.5 个月
      ▼
报告期 + 45 天（≈5/15、8/14、11/14、次年 2/14）  ← 从这天起才"可以看见"
      │
      ▼
每月调仓时：asof(roe_panel, cur) 取"已经能看见的最近一期 ROE"
      │
      └─ 按 ROE 从高到低排序 → 取前 10 只 → 等权买入 → 次日开盘成交
```

**所以 ROE 序列是"阶梯状"的**：

| 日期区间 | 用的是哪期 ROE |
|---|---|
| 2020-05-15 ~ 2020-08-13 | 2020 一季报（3/31 + 45 天） |
| 2020-08-14 ~ 2020-11-13 | 2020 半年报 |
| … | … |

这也是为什么日志里会看到"ROE 最高 47.21%"连续出现好几个月——**一个季度内它只换一次值**。

---

## 三、核心思路

**ROE（净资产收益率）= 净利润 ÷ 净资产**：

$$ROE = \frac{\text{净利润}}{\text{净资产}}$$

它回答的是：**公司用股东的钱，赚钱的效率有多高。**

- ROE = 15% → 每 100 元净资产一年赚 15 元；
- 巴菲特偏爱的"好公司"标准之一就是**长期高 ROE**。

**为什么高 ROE 可能带来超额收益？**

1. **复利效应**：高 ROE 的公司如果持续把利润再投入，净资产和利润会滚雪球；
2. **护城河代理**：能长期维持高 ROE 的公司往往有竞争优势（品牌、规模、网络效应）；
3. **机构偏好**：长期资金偏爱确定性高的优质公司。

> **常见误解**：高 ROE 不一定"好"。
> - **高杠杆推高的 ROE**：借钱扩大分母（净资产）不动，净利润靠负债撬动——这种 ROE 很脆弱；
> - **一次性收益**：卖资产、政府补贴都可能让某期 ROE 异常高；
> - **周期性行业**：钢铁、煤炭在景气顶点的 ROE 极高，但那是周期的顶点，不是"质量"。
>
> 更全面的质量因子应该同时看 **ROE + 毛利率 + 现金流 + 负债率**（本仓库的策略 7 会把 ROE 和估值/动量组合起来）。

## 四、算法结构

```
main() → load_index_members → load_universe → __CAL__ → run_strategy
   │
   └─ QualityROE.__init__()
         └─ self.panel = roe_panel(codes, lag_days=45)     ← 索引整体后移 45 天
   │
   └─ 每月 on_rebalance(cur)
         ├─ row = asof(self.panel, cur)      ← 只取"已公布"的最近一期
         ├─ 样本 < 10 → 不调仓
         ├─ row.sort_values(ascending=False) ← 降序：ROE 越高越好
         ├─ 取前 10 → equal_weight_order()
         └─ 顺手打印本期的最高 ROE（诊断用）
```

**注意：这一篇**没有** `row = row[row > 0]` 这一步。** 为什么？因为负 ROE 是"真实存在的亏损公司"，把它们排在最后（降序）本来就是正确行为，不需要像 PB 那样剔除。

## 五、代码逐段详解

### 5.1 关键参数

```python
START = '2018-01-01'
UNIVERSE_SIZE = 40
TOPN = 10
LAG_DAYS = 45               # 报告期 → 可用日 的滞后天数（近似公告延迟）
```

`LAG_DAYS = 45` 是**本策略最重要的一个参数**：它决定了"你什么时候才知道财报"。

| 改成 | 后果 |
|---|---|
| `0` | 报告期当天就能看到财报 → **未来函数**（大部分公司还没公告） |
| `45` | 折中近似（本仓库默认） |
| `90` | 更保守，但会错过部分已公告信息 |

### 5.2 `__init__`：用 `roe_panel` 做时间平移

```python
class QualityROE(PanelStrategy):
    params = (('topn', TOPN), ('rebalance', 'monthly'),)

    def __init__(self):
        super().__init__()
        codes = [d._name for d in self.tradables]
        self.panel = roe_panel(codes, lag_days=LAG_DAYS)
```

`roe_panel` 内部做的事（btlab 源码）：

```python
s = roe_series(code)                      # 报告期 → ROE
s.index = s.index + pd.Timedelta(days=lag_days)   # ← 索引整体后移 45 天
```

**这一行 `+ 45 days` 就是"防未来函数"的全部秘密**：把"报告期"改写成"可用日"。之后 `asof` 再切一次，就得到"今天已经能看见的最近一期"。

### 5.3 `on_rebalance`：降序取最好

```python
def on_rebalance(self, cur):
    row = asof(self.panel, cur)
    if row is None or len(row) < self.p.topn:
        return
    names = [c for c in row.sort_values(ascending=False).index[:self.p.topn]
             if c in self.getdatanames()]
    top_roe = row.sort_values(ascending=False).iloc[0] if len(row) else float('nan')
    print(f'  [{cur}] ROE 最高 {top_roe:.2f}%')
    self.equal_weight_order(names, cur)
```

| 代码 | 作用 |
|---|---|
| `ascending=False` | **降序** → ROE 最高的排第一（与策略 3/4 的升序相反！） |
| `if c in self.getdatanames()` | 过滤掉面板里有、但行情数据缺失的代码 |
| `print(...)` | **只用于诊断**：让你看见"这一期最好公司的 ROE 是多少"，不参与决策 |

## 八、回测结果怎么读

| 指标 | 数值 | 怎么理解 |
|---|---|---|
| 累计收益率 | **+62.27%** | 跑赢基准（+6.61%） |
| 年化收益率 | **+5.91%** | 中规中矩 |
| 最大回撤 | **−42.18%** | ⚠️ 比小市值还大 |
| 夏普比率 | **0.36** | 全场偏低 |
| 成交笔数 | 895 | 月频换手 |

**为什么"质量因子"的表现反而不如"小市值"？**

1. **区间问题**：2018-2026 覆盖了"核心资产崩盘"（2021 后的白马股杀估值），高 ROE 的公司恰恰是那一批；
2. **单因子太粗**：ROE 高 ≠ 估值合理，买在高位的优质公司一样亏钱；
3. **45 天是近似**：真实公告日有早有晚，会引入误差（偏乐观或偏保守都可能）。

> **教学价值**：这一篇告诉你 —— **好因子 ≠ 好策略**。因子要放到"估值、时机、组合"里才能变成策略。这正是后面策略 7（多因子）要解决的问题。

## 九、易混点与常见错误

| 症状 | 原因 | 正确做法 |
|---|---|---|
| `LAG_DAYS=0` 收益暴涨 | 用了还没公告的财报 | 至少滞后 30～45 天 |
| 以为 ROE 每天变 | 财报是季度的 | 接受"阶梯状"，或用同比/环比平滑 |
| 排序方向反了 | 用了升序 | ROE 越高越好 → `ascending=False` |
| 以为这是真实公告日 | 45 天是**近似** | 需要精确公告日请用聚宽 `get_fundamentals` 的历史公告日 |

## 十一、改进方向（思考题）

1. **改滞后天数**：试 `LAG_DAYS = 30 / 60 / 90`，观察收益变化——理解"你对财报时效的假设有多重要"。
2. **加杠杆过滤**：同时取资产负债率，剔除"靠借钱堆出来的高 ROE"。
3. **组合质量 + 估值**：把 ROE 和 PB 一起用（见策略 7），解决"好公司但太贵"的问题。
4. **用 ROE 变化率**：从"ROE 高"改成"ROE 在改善"，捕捉景气上行。
