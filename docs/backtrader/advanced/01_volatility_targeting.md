## 二、心智模型：把"波动"当成油门

```
每周第一个交易日（收盘后）
   │
   ├─ 1. 取最近 21 个收盘价 → 20 个日收益率
   ├─ 2. 年化波动率 = 日收益率标准差 × √252
   │        （252 = A 股一年约 252 个交易日）
   │
   ├─ 3. 目标仓位 = 目标波动率 ÷ 已实现波动率
   │        · 市场平静（vol 小）→ 仓位大
   │        · 市场动荡（vol 大）→ 仓位小
   │
   ├─ 4. 封顶：仓位不超过 100%（max_leverage=1.0）
   │
   └─ 5. self.order_target_percent(target=仓位) → 次日开盘成交
```

**一张数字表看懂它的行为**（假设目标波动率 15%）：

| 已实现波动率 | 原始公式 15%/vol | 实际仓位（封顶 1.0） | 含义 |
|---|---|---|---|
| 8%（市场很平静） | 1.88 | **1.00** | 满仓（想加杠杆但被上限挡住） |
| 15%（刚好） | 1.00 | **1.00** | 满仓 |
| 30%（动荡） | 0.50 | **0.50** | 半仓 |
| 60%（极端） | 0.25 | **0.25** | 只留四分之一仓 |

**直觉**：这不是"预测涨跌"，而是**"波动大的时候少下注"**——就像开车时路面滑就减速。

## 三、核心思路

**传统做法**：永远 100% 仓位。问题：牛市里波动大、熊市里波动也大，**你的风险暴露完全不受控**。

**波动率目标（Volatility Targeting）**：

$$w = \min\left(\frac{\sigma_{target}}{\sigma_{realized}},\ \text{max\_leverage}\right)$$

- $\sigma_{target}$：你希望组合承受的年化波动率（本策略 15%）；
- $\sigma_{realized}$：过去 20 个交易日的实际年化波动率；
- 波动越小 → 仓位越大；波动越大 → 仓位越小。

**为什么有效？**

1. **波动率有聚集性（volatility clustering）**：高波动往往跟着高波动，所以"今天的高波动"对近期有预测力——这是少数**可预测**的东西（收益率方向难预测，波动率相对好预测）；
2. **风险平价的思想**：让每一段时间贡献的"风险"大致相等；
3. **改善风险调整收益**：通常能降低回撤、提高夏普（但会牺牲一点牛市收益）。

> **常见误解**：波动率目标**不是**择时策略，它不预测涨跌。它只是把"风险敞口"标准化——**上涨时可能少赚，下跌时也少亏。**
>
> **⚠️ 一个现实约束**：波动率极低时公式会给出 >100% 的仓位（加杠杆买），但 A 股 ETF 不能轻易加杠杆，所以必须 `min(..., 1.0)` 封顶。**不封顶的回测能跑出很漂亮的曲线，但那是不可实现的。**

## 四、算法结构

```
main() → load_daily('510300') → run_strategy(VolTarget, {...})
   │
   └─ VolTarget.next()（每根日线都调用）
         ├─ week = cur.isocalendar()[:2]
         ├─ week == self._last_week ? → return（这就是"每周只调一次"）
         ├─ closes = self.data.close.get(size=21)       ← array，最旧→最新
         ├─ rets = pd.Series(closes).pct_change().dropna()
         ├─ vol = rets.std() * sqrt(252)                ← 年化波动率
         ├─ w = min(target_vol / vol, max_leverage)
         └─ self.order_target_percent(target=w)         → 次日开盘调仓
```

## 五、代码逐段详解

### 5.1 参数

```python
LOOKBACK = 20               # 波动率估计窗口（交易日）
TARGET_VOL = 0.15           # 目标年化波动率 15%
MAX_LEVERAGE = 1.0          # 最大仓位（1.0 = 不加杠杆，最多满仓）

params = (('lookback', LOOKBACK), ('target_vol', TARGET_VOL),
          ('max_leverage', MAX_LEVERAGE),)
```

| 参数 | 改了会怎样 |
|---|---|
| `LOOKBACK` | 20 → 60：波动率估计更平滑、调仓更慢；→ 10：更灵敏、更容易频繁调仓 |
| `TARGET_VOL` | 0.15 → 0.25：整体仓位更高（收益和回撤一起变大） |
| `MAX_LEVERAGE` | 设 >1（如 1.5）会加杠杆——**A 股 ETF 做不到，不要这样回测** |

### 5.2 `next()`：周度检测 + 波动率估计

```python
def next(self):
    cur = self.data.datetime.date(0)
    week = cur.isocalendar()[:2]              # (ISO 年, ISO 周)
    if week == self._last_week:
        return                                # 本周已经调过 → 直接返回
    self._last_week = week                    # 记住这一周

    closes = self.data.close.get(size=self.p.lookback + 1)
    if len(closes) < self.p.lookback + 1:
        return                                # 数据不足，跳过
    rets = pd.Series(closes, dtype=float).pct_change().dropna()
    vol = float(rets.std() * (252 ** 0.5))    # 年化波动率
    if vol <= 1e-6:
        return                                # 波动为 0（异常）→ 跳过
    w = min(self.p.target_vol / vol, self.p.max_leverage)
    self.weights.append(w)                    # 记录，供 stop() 统计
    self.order_target_percent(target=w)
```

| 这一行 | 为什么 |
|---|---|
| `isocalendar()[:2]` | 返回 `(ISO 年, ISO 周)`，用元组比较就能实现"换周才执行" |
| `get(size=21)` | 算 20 个日收益率需要 21 个价格点；返回 **array**（`[0]` 最旧、`[-1]` 最新） |
| `pct_change().dropna()` | 差分出日收益率，并去掉第一个 NaN |
| `std() * sqrt(252)` | **年化**：标准差是"日的"，乘 √252 换算成"年的" |
| `if vol <= 1e-6: return` | 防止除零 |
| `order_target_percent(target=w)` | 把 `self.data` 调到总资产的 w 倍 |

> **`order_target_percent` 的坑**：它按 `目标市值 ÷ 价格` 直接算股数，**不知道 A 股要 100 股一手**。本策略标的是 ETF（同样 100 份起），所以严格来说会产生"零头"。教学场景可接受；要严谨就自己 `round_lot` 后 `self.buy/sell`（本仓库其他策略就是这么做的）。

### 5.3 `stop()`：诊断输出

```python
def stop(self):
    if self.weights:
        print(f'  仓位区间 {min(self.weights) * 100:.1f}% ~ '
              f'{max(self.weights) * 100:.1f}%，平均 {sum(self.weights) / len(self.weights) * 100:.1f}%')
```

**为什么要打印？** 因为这一篇的"核心行为"就是仓位变化。不看仓位分布，你无法判断策略有没有按预期工作（比如仓位长期贴着 100%，说明波动率很少超过 15%）。

## 六、一次真实运行的轨迹

```
[1/2] 加载 510300 日线（含分红口径）...
      区间 2013-01-04 ~ 2026-09-30，共 3338 个交易日
[2/2] 开始 backtrader 回测 ...
  仓位区间 21.3% ~ 100.0%，平均 78.4%
```

**怎么读这行输出**：

- **下界 21.3%**：说明历史上最动荡的时候，策略把仓位降到了两成左右（比如 2015 股灾、2020 年 3 月）；
- **上界 100%**：说明也有满仓的时候（波动率 ≤ 15%）；
- **平均 78.4%**：长期平均仓位不到 8 成——**这也解释了为什么它的收益通常低于满仓持有**。

## 七、与聚宽版的差异

| 维度 | 聚宽 | 本地版 |
|---|---|---|
| 定时 | `run_weekly(rebalance, 1)` | `isocalendar()[:2]` 变化检测 |

| 标的 | 510300.XSHG | 510300（btlab 自动归一化） |

**注意**：backtrader 的 `order_target_percent` 与聚宽的 `order_target_percent` 语义一致（都是"调到总资产的比例"），这一篇是少数**两个框架写法几乎一样**的策略。

## 八、回测结果怎么读

| 指标 | 数值 | 怎么理解 |
|---|---|---|
| 累计收益率 | **+103.76%** | —— |
| 年化收益率 | **+5.52%** | 低于满仓持有（基准 +72.62%）吗？不，是**高于** |
| 最大回撤 | **−35.39%** | 明显小于基准（沪深300 同期回撤远大于此） |
| 夏普比率 | **0.45** | 优于策略 1（0.10） |
| 同期基准 | +72.62% | 累计收益更高，但回撤也更大 |
| 成交笔数 | 344 | 周频调仓，约 13 年 690 周 |

**要点：**

1. **典型的"风险调整后更优"**：累计收益 +103.76% > 基准 +72.62%，而最大回撤 −35.39% 小于基准；
2. **代价是"平均只有 78% 仓位"**：如果满仓做同样的事，收益会更高，但回撤也更大——**这就是风险预算的取舍**；
3. **周频调仓带来 344 笔成交**，成本不可忽略。

> **教学价值**：这一篇第一次把"仓位"从 0/1（满仓/空仓）变成**连续变量**。你会看到"控制风险"本身就能创造价值，而不是只有"选对方向"才创造价值。

## 九、易混点与常见错误

| 症状 | 原因 | 正确做法 |
|---|---|---|
| 回测收益虚高 | `max_leverage > 1` 允许加杠杆 | 设 1.0（A 股 ETF 不能加杠杆） |
| 仓位算出来是 5 倍 | 波动率极低没封顶 | `min(target_vol/vol, max_leverage)` |
| 每天调仓 | 没做周检测 | `week == self._last_week → return` |
| `len(closes)` 永远不够 | `get(size=n)` 在数据不足时返回更短的数组 | 显式判断 `len(closes) < lookback+1` |
| 买了零头股数 | `order_target_percent` 不懂整手 | 自己 `round_lot` 后用 `buy/sell` |
| 波动率算成"日的" | 忘了乘 √252 | 年化 = 日标准差 × √252 |
