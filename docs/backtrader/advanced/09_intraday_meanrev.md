# 进阶策略 9：短期均值回归 / 超跌反弹策略（日线降频版）· backtrader 本地版

> 类型：均值回归 / 反转 ｜ 难度：★★★★★ ｜ 前置知识：PanelStrategy 周频调度、hist_close、close_all
> **运行框架：backtrader（本地回测 + 免费数据）** ｜ 本策略的**聚宽云端版**见 [docs/joinquant/advanced/09_intraday_meanrev.md](../../joinquant/advanced/09_intraday_meanrev.md)

> ⚠️ **重要声明（数据受限导致的降级）**：本策略的**原始思路是「日内超跌反弹」**（用分钟级数据，捕捉开盘后 30 分钟内暴跌 ≥2% 后的日内反弹）；但本地**免费数据源没有稳定的分钟级行情**（东财分钟接口常被限流/不可达），所以本 backtrader 版**降级为日线版**——改为「过去 5 个交易日累计跌幅超过阈值 → 反弹」的短期反转策略。
> 这**不是原始完整实现的复刻**：时间尺度从「分钟」放大到「日」，持仓周期从「日内（隔日卖，受 T+1 约束）」拉长到「约一周」。均值回归/过度反应修复的**原理一致**，但交易结构、成本、风险特征都已改变。若要做真正的分钟级回测，需自行接入 tushare / 米筐等付费分钟数据源，策略骨架可复用。下文凡涉及回测结论，均指「降级后的日线版」，请勿等同于原始日内思路。

## 一、核心思路

核心逻辑是「**超跌反弹**」（均值回归）：股票短期大幅下跌后，往往出现反弹。本降级版每周扫描全池，选出「过去 5 个交易日累计跌幅最大、且超过阈值」的股票，取跌幅最大的 TOPN 只等权买入，持有到下个调仓日（约 5 个交易日）后自然退出。

为什么会有这种「过度反应」？行为金融学解释：投资者对突发负面信息**反应过度**（over-reaction），价格短期跌过头，随后理性资金进场把价格拉回合理水平。

给新手的直觉：弹簧压得太狠会回弹。但「超跌」不等于「一定反弹」——有些暴跌是基本面真坏了（暴雷），会持续跌（接飞刀）。所以本策略靠「全池筛选 + 严格阈值 + 空仓纪律」控制风险：没有满足超跌条件的股票时，**空仓**而不是硬凑 10 只。

```
5 日累计跌幅（回看窗口 WINDOW=5）：
    drop = close[-1] / close[0] - 1.0          # close 来自 list.get()，list[-1]=最新
    选 drop <= THRESHOLD(-0.08) 且跌幅最大的 TOPN 只
```

### 均值回归直觉（给新手）

均值回归是金融里最经典的规律之一：**价格跌多了会涨回来，涨多了会跌回来**，长期围绕「合理价值」波动。它和「动量」正好相反：

- **动量**：涨的继续涨（强者恒强），适用于中期（1~12 个月）；
- **均值回归**：跌的会反弹（物极必反），适用于短期（日内~1 周）。

两者看似矛盾，其实适用于不同时间尺度——短期情绪化超买超卖会修复，中期趋势一旦形成会延续。本降级版抓的是「周度反转」：一周跌太狠的股票，下一周倾向于修复。但必须记住：均值回归是「概率」不是「必然」，暴跌可能是基本面真坏了（暴雷会持续跌），所以空仓纪律和止损比信号本身更重要。

## 二、算法结构（分步拆解）

```
每周第 1 个交易日触发 on_rebalance(cur)        # rebalance='weekly'，约持有 5 个交易日
   │
   ├─ 1. 遍历 self.tradables，live() 过滤停牌/未上市
   │      └─ hist_close(d, WINDOW+1) 取 6 个收盘价
   ├─ 2. 算每只 5 日累计跌幅 drop = closes[-1] / closes[0] - 1.0
   ├─ 3. 只保留 drop <= THRESHOLD(-0.08) 的超跌股（oversold）
   │      └─ 一个都没有 → close_all(cur) 空仓，return
   └─ 4. 取跌幅最大（drop 最小）的 TOPN 只 → equal_weight_order(names, cur)
```

## 三、代码逐段详解 + backtrader 语法解析

### 3.1 `rebalance='weekly'` —— 周频调度

`PanelStrategy`（`btlab/runner.py:225`）的 `params` 支持 `'daily' / 'weekly' / 'monthly'`。周频时 `next()` 用 `cur.isocalendar()[:2]`（年+周号）去重，每周只在第 1 个交易日触发一次 `on_rebalance`。这是 backtrader 与聚宽 `run_daily(time='09:35')` 分钟级调度的对应物——但本地只能做到周频，因为无分钟数据。周频意味着持仓约 5 个交易日，比日内版「隔日卖」的持有期长得多。

### 3.2 超跌判定与 list 索引语义（重点）

```python
closes = self.hist_close(d, self.p.window + 1)    # 6 个收盘价
if closes is None or closes[0] <= 0:
    continue
scores[d._name] = closes[-1] / closes[0] - 1.0    # 5 日累计涨跌幅
```

`hist_close` 内部 `d.close.get(size=6)` 返回 **`array.array`**（不是 Python list；最旧在前、最新在后）。所以 `closes[0]` = 6 根前（5 日前）收盘价、`closes[-1]` = 当根（最新）收盘价，`closes[-1]/closes[0]-1` 即「过去 5 个交易日累计涨跌幅」。这与 base doc §2.2 强调的 Line 索引不同：`d.close[0]` 才是 Line 的当根、`d.close[-1]` 是昨天；而 `.get()` 返回的 list 里 `[-1]` 是最新——**千万别把两种语义混用**。

`hist_close` 在 `len(d) < 6` 时返回 `None`，挡住首根 K 线负索引绕圈的未来函数陷阱。

### 3.3 超跌筛选与空仓纪律

```python
oversold = {k: v for k, v in scores.items() if v <= self.p.threshold}
if not oversold:
    self.close_all(cur)        # 没有超跌股 → 空仓
    return
names = sorted(oversold, key=oversold.get)[:self.p.topn]   # 跌得最狠的优先
self.equal_weight_order(names, cur)
```

只保留「跌幅 ≤ 阈值（-8%）」的股票；若全市场都在涨（没有超跌股），`close_all` 清仓空仓等待——这是反转策略必须的纪律，避免「为了交易而交易」。`sorted(..., key=oversold.get)` 按跌幅升序，取跌得最深的前 TOPN 只（跌越深、反弹空间理论上越大，但「接飞刀」风险也越高）。

### 3.4 降级实现带来的特征变化

| 维度 | 原始日内思路（聚宽） | 本降级日线版 |
|------|---------------------|--------------|
| 信号窗口 | 开盘 30 分钟内跌 2% | 过去 5 日累计跌 8% |
| 持仓周期 | 日内（T+1 次日卖） | 约 5 个交易日（周频） |
| 时间尺度 | 分钟 | 日 |
| 信号噪声 | 极高（分钟噪声大） | 较低（日线更平滑） |

降级让策略从「高频博反弹」变成「周度反转」：持仓变长、交易次数变少，但**单笔错误持仓的回撤暴露时间也更长**（见第五节 -66.75% 最大回撤）。这不是「更优」，只是「在免费数据约束下可运行的最接近实现」。

### 3.5 关键参数表

| 参数 | 默认 | 含义 |
|------|------|------|
| `UNIVERSE_SIZE` | 40 | 沪深300 前 40 只（幸存者偏差） |
| `TOPN` | 10 | 持有超跌股数 |
| `WINDOW` | 5 | 回看交易日数（算累计跌幅） |
| `THRESHOLD` | -0.08 | 超跌阈值（累计跌超 8%） |
| `rebalance` | 'weekly' | 每周第 1 个交易日调仓 |

### 3.6 backtrader 索引方向速查（防未来函数，必记）

| 写法 | 含义 | 能否在回测中用 |
|------|------|----------------|
| `d.close[0]` | 当根收盘价（Line 索引） | ✅ |
| `d.close[-1]` | 上一根（昨天） | ✅ |
| `d.close[-2]` | 上上根（前天） | ✅ |
| `d.close[1]` | 下一根（明天） | ❌ 未来数据，禁用 |
| `d.close.get(size=n)` 返回的 array | `[0]`=最旧、`[-1]`=最新（数组） | ✅（序列语义，与 Line 相反） |

本策略 `closes[-1]/closes[0]-1` 里 `closes` 是 `hist_close` 返回的 array，`[-1]`=最新、`[0]`=5 日前。两个易错点：**(1)** `line[1]` 是未来，禁用；**(2)** 首根 K 线 `[-1]` 会绕到数据集末尾（base doc §2.2），靠 `hist_close` 的 `len(d)<n` 判空挡住。

### 3.7 降级后时序与持仓周期的变化（诚实复盘）

| 维度 | 原始日内思路（聚宽） | 本降级日线版 |
|------|---------------------|--------------|
| 信号窗口 | 开盘 30 分钟内跌 2% | 过去 5 日累计跌 8% |
| 持仓周期 | 日内（T+1，今买明卖） | 约 5 个交易日（周频） |
| 单笔错误暴露 | 1 天内平仓 | 最长拿 1 周 |

降级让「快进快出」变成「周度持有」：好处是信号噪声更低（日线比分钟平滑），坏处是**单笔踩雷的回撤暴露时间拉长一倍**——这正是第五节 -66.75% 深回撤的根源之一（见第五节解读）。这不是策略变优，是免费数据约束下的折中。

### 3.8 `close_all` 与空仓纪律

`PanelStrategy.close_all(cur)` 遍历 `self.tradables`，对「有持仓且当天有行情」的标的调 `self.close(d)`：

```python
def close_all(self, cur=None):
    for d in self.tradables:
        if self.getposition(d).size and self.live(d, cur):
            self.close(d)
```

反转策略**必须**有空仓纪律：全市场都在涨、没有超跌股时，`close_all` 清仓等待，绝不为了交易硬凑 10 只——否则会把「普通上涨股」当超跌买进来，逻辑全乱。

### 3.9 回测时序

`on_rebalance(cur)` 在当根收盘后调用（周频，约每 5 个交易日一次），`self.buy/sell` 默认**下一根开盘**成交（base doc §9.1），天然防未来。`cur` 取自 `self.cal.datetime.date(0)`，用 `__CAL__` 基准当日历源，避免某 ETF 停牌时拿不到当前日期（base doc §4.3）。

### 3.10 均值回归策略常见坑

1. **接飞刀**：暴跌可能是基本面真坏了（暴雷），会持续跌不反弹——本策略无止损，单笔大亏会拿满一周。
2. **噪声**：日线虽比分钟平滑，但 5 日窗口仍可能捕捉到随机波动而非真实超跌。
3. **T+1 约束**：A 股当日买入次日才能卖，周频调仓天然规避了「日内买、隔日卖」的 T+1 摩擦，但也失去了日内快进快出的灵活性。
4. **阈值敏感**：`-8%` 阈值过松会少信号、过紧会接飞刀，需样本外调参而非过度拟合。

### 3.11 与 a06/a07/a08 的风险定位

本策略最大回撤 -66.75% 是 5 篇里最深，夏普 0.50 最低。原因：周度反转押注「跌最狠」的股票，本质是「高贝塔 + 逆向」，一旦市场系统性下跌（2015/2018/2022）会连续踩雷；且周频持仓让亏损暴露时间更长。相比之下 a07 因子择时（防守 regime 切换）回撤 -33%、a08 ML 因子 -31%，都因有估值/质量过滤而更稳。反转策略需要额外止损才能降波动——这点在第六节改进方向里展开。

## 四、与聚宽版的差异

| 维度 | 聚宽版 a09 | backtrader 本地版 |
|------|-----------|-------------------|
| 数据频率 | **分钟级**（`every_bar`，开盘 30 分钟） | **日线**（无免费分钟数据 → 降级） |
| 超跌信号 | 开盘以来跌幅 ≤ -2% | 过去 5 日累计跌幅 ≤ -8% |
| 持仓周期 | 日内（T+1，今买明卖） | 约 5 个交易日（周频） |
| 触发方式 | `run_daily(time='09:35')` | `PanelStrategy` 周频 `on_rebalance` |
| 下单口径 | `order_target_value` | `equal_weight_order` → `round_lot` 整手 |
| 费用/滑点 | `set_order_cost(type='stock')` + `FixedSlippage(0.02)` | `AStockCommission` + `set_slippage_perc(0.0002)` |
| 数据可得性 | 云端有分钟行情 | **免费源无分钟数据 → 被迫降频（本例特有）** |

**数据可得性差异（本例特有，必须知道）**：聚宽云端能取 `get_price(freq='minute')` 做真日内；本地免费源（akshare 分钟接口不稳定）拿不到可靠分钟数据，所以降到日线。这改变了策略的「时间尺度」和「成本结构」——日内策略的核心优势（快进快出、成本控制）在日线版里基本消失，而「接飞刀」的单笔大亏风险因持仓变长被放大。回测数字只能代表降级版，不能外推到原始日内思路。

## 六、改进方向（思考题）

1. **加个股止损**：单笔持仓跌超 5%~8% 即砍仓，可显著压低 -66.75% 的最大回撤（反转策略最怕「接飞刀」不止损）。
2. **过滤基本面暴雷**：超跌前排除 ST/退市/业绩雷，避免把「真坏」当「超跌」。
3. **若能拿到分钟数据**：改回原始日内思路（开盘 30 分钟跌 2% 博反弹），用 T+0 品种（ETF/可转债）规避 T+1；届时需重新评估扣费后的真实收益——日内策略成本才是命门。
