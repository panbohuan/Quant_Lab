## 一、这一篇你将学到什么

这一篇最重要的不是策略，而是**"数据可得性如何决定策略定义"**——本仓库最值钱的一课。

| 你会搞懂 | 一句话 |
|---|---|
| 可转债的"债性 + 股性" | 下有保底、上不封顶 |
| 经典"双低"公式 | 转债价格 + 转股溢价率 |
| **为什么本地版做不了真双低** | 免费源只有"当前"溢价率 → 用它就是未来函数 |
| 由此的取舍 | 退化为"只用历史价格的低价轮动" |
| 可转债数据的特殊性 | 代码段、覆盖率门槛、T+0 |

**读完你应该能回答**：为什么"用了当前溢价率"是作弊，而不是"数据不够精确"？

## 二、心智模型：从"双低"降级到"低价"

```
每月第一个交易日（收盘后）
   │
   ├─ 1. 遍历候选转债（上市早于 2019、数据覆盖率 ≥ 50%）
   ├─ 2. 取每只转债的当前价格
   ├─ 3. 按价格升序取最低的 5 只
   └─ 4. 等权买入 → 次日开盘成交
```

**本来是"双低"**：`双低值 = 转债价格 + 转股溢价率(%)`，越小越便宜。
**实际只能做"低价"**：因为**历史转股溢价率拿不到**（详见第三节）。

**一张数字表看"低价"选出来的是什么**：

| 转债 | 现价 | 转股溢价率 | 真双低值 | 本策略排序依据 |
|---|---|---|---|---|
| A | 98 | 45% | 143 | **第 1（价格最低）** |
| B | 105 | 8% | 113 | 第 2 |
| C | 130 | 2% | 132 | 第 3 |

**注意**：真正的"双低"会选 B（143 > 113），而本策略会选 A（98 < 105）。**两者选出来的东西不一样。**

## 三、核心思路

**可转债 = 债券 + 看涨期权**：

- **债性**：股价不涨，至少还本付息 → 提供**下行保护**（价格接近 100 元时"债底"明显）；
- **股性**：股价大涨，可以转股跟着赚 → 提供**上行弹性**。

**经典"双低"策略**想同时要两件事：

| 维度 | 含义 | 为什么好 |
|---|---|---|
| 价格低 | 接近债底 | 下跌空间小 |
| 溢价率低 | 转债价与转股价值差距小 | 跟涨能力强 |

> **⚠️ 数据可得性这一课（本篇核心）**
>
> `load_bond_universe()` 返回的 `转股溢价率` 是**当前时点快照**——也就是说，"今天的溢价率"。
>
> 如果拿它去给 2019 年的每一天排序：
> - 你等于**用 2026 年的信息**决定 2019 年买什么 → **未来函数**；
> - 回测会因此虚高，而且**虚高多少你无法估计**。
>
> 所以本策略**主动放弃**溢价率这一维，只用**可得的历史价格**。这是量化研究里非常常见的一步：**先问"数据支不支持这个策略"，再谈策略本身。**
>
> 想要真正的双低，只有两条路：① 用聚宽（有历史溢价率）；② 接入能回放历史溢价率的付费数据源。

## 四、算法结构

```
main()
 ├─ build_bond_universe()
 │     ├─ listed_bonds(before='2019-01-01', top=60)     按发行规模取候选
 │     ├─ 逐只 load_bond_daily(code, start, end)         拉转债日线
 │     ├─ 覆盖率 < 50% 的剔除（防数据断层）
 │     └─ 返回 {转债代码: DataFrame} + data['__CAL__']
 └─ run_strategy(LowPriceBond, data, ...)
       │
       └─ 每月 on_rebalance(cur)
             ├─ 遍历 tradables：live(d,cur) 且 price > 0
             ├─ 按价格升序取最低的 5 只
             └─ equal_weight_order()
```

## 五、代码逐段详解

### 5.1 参数与候选池

```python
START, END = '2019-01-01', '2025-06-30'
MAX_CANDIDATES = 60         # 候选池：按发行规模取前 N 只
MIN_COVERAGE = 0.50         # 数据覆盖度下限
TOPN = 5                    # 持有价格最低的 5 只
```

| 参数 | 为什么这么定 |
|---|---|
| `MAX_CANDIDATES=60` | 全市场转债有上千只，逐只拉数据太慢；按**发行规模**取前 60 只（规模大的流动性好） |
| `MIN_COVERAGE=0.50` | 转债有上市/退市，覆盖率太低说明数据有断层 |
| `START='2019-01-01'` | 转债数据在免费源里较晚才有 |
| `TOPN=5` | 转债样本少（本回测只有 11 只可用），持有太集中风险大、持有太多没意义 |

### 5.2 候选池构建（本篇的工程重点）

```python
def build_bond_universe():
    table = listed_bonds(before=START, top=MAX_CANDIDATES)
    total_days = len(pd.bdate_range(pd.Timestamp(START), pd.Timestamp(END)))
    data = {}
    for _, row in table.iterrows():
        code = row['bond_code']
        try:
            df = load_bond_daily(code, start=START, end=END)
        except Exception:
            continue                                    # 拉不到就跳过
        if len(df) < total_days * MIN_COVERAGE:          # 覆盖率不足 → 剔除
            continue
        data[bond_symbol(code)] = df                    # ← 用归一化后的转债代码当名字
    data['__CAL__'] = load_daily(BENCHMARK, start=START, end=END)
    return data
```

| 细节 | 说明 |
|---|---|
| `listed_bonds(before=START, top=...)` | 取"在 START 之前就上市"的转债，避免"未卜先知" |
| `bond_symbol(code)` | 转债代码归一化：沪市 `110/111/113/118` → `sh`，深市 `123/127/128` → `sz`（**与股票的 `normalize_code` 规则不同**） |
| `total_days * MIN_COVERAGE` | 用**工作日**近似交易日（略偏严格，是安全的近似） |
| `except Exception: continue` | 单只转债拉失败不能毁掉整个回测 |

### 5.3 选券：一行就是全部策略

```python
def on_rebalance(self, cur):
    scored = {}
    for d in self.tradables:
        if not self.live(d, cur):
            continue
        price = d.close[0]
        if price > 0:
            scored[d._name] = price
    if len(scored) < self.p.topn:
        return
    target = sorted(scored, key=scored.get)[:self.p.topn]   # 升序 = 最便宜
    self.equal_weight_order(target, cur)
```

**对照策略 2/3/4**：结构完全一样（遍历 → 取数 → 排序 → 等权）。**唯一的区别是"用什么值排序"。**

## 六、一次真实运行的轨迹

```
[1/3] 从已上市转债中取发行规模最大的 60 只 ...
      候选 60 只（上市时间均早于 2019-01-01）
[2/3] 加载转债日线并检查数据覆盖度 ...
      数据可用转债 11 只（覆盖度 >= 50%）
[3/3] 开始 backtrader 回测 ...
    累计收益率      :    41.86%
    最大回撤        :   -10.07%
```

**"60 只候选只有 11 只可用"** 说明什么？

- 免费转债日线接口能拿到的长历史不多；
- 再加上"2019 年前上市 + 覆盖率 ≥50%"的筛选，样本剩 11 只；
- **11 只的等权组合，风险分散度有限**——这是本篇结论可信度的主要限制。

## 七、与聚宽版的差异

| 维度 | 聚宽 | 本地版 |
|---|---|---|
| 转债列表 | `get_all_securities(types=['cb'])`（时点全市场） | `listed_bonds()`（**当前还存续**的，幸存者偏差） |
| **因子** | **真实双低**（价格 + 历史溢价率） | **只有低价**（历史溢价率不可得） |
| 覆盖度 | 平台保证 | 手动 `MIN_COVERAGE` |
| 区间 | 平台设置 | 固定 2019-01 ~ 2025-06 |

## 八、回测结果怎么读

| 指标 | 数值 | 怎么理解 |
|---|---|---|
| 累计收益率 | **+41.86%** | 6.5 年，跑赢基准（+32.55%） |
| 年化收益率 | **+5.76%** | 一般 |
| 最大回撤 | **−10.07%** | ✅ **全场最小** |
| 夏普比率 | **0.77** | 较高 |
| 年化波动率 | **7.65%** | **全场最低** |

**要点：**

1. **"低回撤 + 低波动"是可转债的真实特性**（债底保护），这一篇是全仓库风险特征最好的一篇；
2. **收益不高**：低价转债的代价是弹性差——涨得慢；
3. **两条必须记住的限制**：① 因子已从"双低"降级为"低价"；② 样本只有 11 只、且只用"当前还存续"的转债。

> **教学价值**：这一篇教会你 **"因数据放弃一半策略"**，以及**如何诚实地标注这个降级**。这比"多赚几个点"重要得多。

## 九、易混点与常见错误

| 症状 | 原因 | 正确做法 |
|---|---|---|
| 收益虚高 | 用了当前溢价率快照排序 | 那是未来函数；本地版只用价格 |
| 以为这是"双低" | 名字 ≠ 实现 | 因子已降级为"低价" |
| 转债代码取不到数据 | 用了股票的 `normalize_code` | 转债用 `bond_symbol()` |
| 样本太少 | 覆盖率门槛 + 区间限制 | 放宽 `MIN_COVERAGE` 或拉长区间 |
| 忘记 T+0 | 可转债当日可回转交易 | 本策略按日线月度调仓，未模拟日内回转 |

## 十一、改进方向（思考题）

1. **还原动态溢价率**：用"正股历史价 + 历史转股价"自己算 `溢价率 = 转债价/转股价值 − 1`（需要转股价的历史，免费源仍然拿不到）。
2. **加双低的下修博弈**：筛选"可能触发转股价下修"的转债。
3. **扩样本**：放宽 `MIN_COVERAGE`、纳入期间上市/退市的转债（用最后成交价冻结）。
4. **加止盈**：转债涨到 130 元以上常触发强赎，可以设一个止盈线。
