## 0. 先搞清楚：本仓库有两套策略，互不影响

| | **A 组：聚宽原生策略** | **B 组：backtrader 本地策略** |
|---|---|---|
| 位置 | `strategies/joinquant/{beginner,advanced}/` | `strategies/backtrader/{beginner,advanced}/` |
| 数量 | 20 个（`s01`~`s10`、`a01`~`a10`） | 20 个（`bt_s01`~`bt_s10`、`bt_a01`~`bt_a10`） |
| 运行环境 | **聚宽官网云端**（浏览器里跑） | **本机**（Python 脚本） |
| 需要账号吗 | 需要免费注册聚宽 | **不需要任何账号** |
| 需要装依赖吗 | **完全不需要** | 需要 `pip install -r requirements.txt` |
| 数据来源 | 聚宽平台内置数据 | 免费公开数据源（akshare） |
| API 风格 | `initialize` / `run_daily` / `attribute_history` / `order_target_value` | `bt.Strategy` / `Cerebro` / `next()` / `self.buy()` |
| 回测内核 | 聚宽平台引擎 | **backtrader 官方引擎** |

**A 组怎么跑**：登录 [聚宽](https://www.joinquant.com) → 「我的策略」→ 新建策略 → 把文件内容整段粘贴进去 → 点「编译运行」。
文件里没有任何 `import`、没有本地入口，是纯粹的聚宽原生代码，**改坏了 B 组也不会影响 A 组**。

**B 组怎么跑**：见下面第 2、3 节。

---

> **重要声明**：B 组的回测内核是 **backtrader 官方开源框架**，本仓库**没有自己写回测引擎**。
> `btlab/` 只负责"数据适配 + 样板代码封装"（拉数据、算绩效、画图、A 股手续费模型），
> 行情推进、撮合、持仓、账务、盈亏、净值全部由 backtrader 的 `Cerebro` / `Broker` 完成。

## 1. 环境准备

### 1.1 Python 版本

建议 **Python 3.10 ~ 3.13**。本仓库实际在 **Python 3.13** 上验证通过。
请使用**真实安装的 Python**（python.org 安装包或托管版），不要用微软商店的别名。

### 1.2 建虚拟环境并装依赖

在项目根目录执行：

```bash
python -m venv .venv
.venv\Scripts\activate          # Windows
# source .venv/bin/activate     # macOS / Linux

pip install -r requirements.txt
```

国内网络建议加镜像源：

```bash
pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

核心依赖只有 6 个：`backtrader`、`akshare`、`pandas`、`numpy`、`matplotlib`，
以及 ML 策略需要的 `scikit-learn`（`bt_s08` 另外需要 `statsmodels`）。

### 1.3 在 PyCharm 里配置

`File → Settings → Project → Python Interpreter → Add Interpreter → Existing`，
选中 `.venv/Scripts/python.exe`。之后打开任意 `bt_*.py`，右键 **Run** 即可。

## 2. 跑一个 backtrader 策略

```bash
python strategies/backtrader/beginner/bt_s01_ma_cross.py
```

输出分三部分：

1. **数据加载提示**：例如 `区间 2013-01-04 ~ 2026-09-30，共 3338 个交易日`；
2. **绩效报告**：累计/年化收益率、基准对比、超额收益、最大回撤、夏普比率、
   年化波动率、日胜率、成交笔数、累计换手率、回测区间；
3. **净值图**：上图为「策略净值 vs 基准净值」，下图为「回撤曲线」，
   保存到 `results/bt_s01_result.png`。

每个策略文件顶部都有一块 `# ===== 回测参数（改这里即可） =====`：

```python
START = '2013-01-01'        # 数据起点
END = None                  # None = 到今天
CASH = 1_000_000            # 初始资金
BENCHMARK = '000300'        # 基准：沪深300指数
UNIVERSE_SIZE = 40          # 股票池大小（只对选股类策略有效）
TOPN = 10                   # 持仓只数
LOOKBACK = 60               # 因子回看期
```

策略自身的参数写在 `class XXX(PanelStrategy).params` 里
（均线周期、阈值、调仓频率 `rebalance='monthly'/'weekly'/'daily'` 等）。

### 2.1 批量运行

仓库根目录的批量脚本可一次跑完全部 20 个策略并把日志写到 `results/logs/`。
也可以直接循环：

```bash
for f in strategies/backtrader/beginner/bt_*.py strategies/backtrader/advanced/bt_*.py; do
  python "$f"
done
```

## 3. 数据从哪来（免费、长历史）

数据全部由 `btlab/datasource.py` 从**公开数据源**抓取，**不需要注册、不需要 API Key**：

| 数据 | 来源 | 历史起点 | 对应聚宽 API |
|------|------|----------|--------------|
| 股票日线（前/后复权） | 新浪财经 | 1990 年代 | `get_price` / `attribute_history` |
| 指数日线 | 新浪财经 | 2000 年代 | `get_price`（指数） |
| ETF 日线 | 新浪财经 | 上市日起 | `get_price`（ETF） |
| 指数成分股 | 中证指数官网 | 最新成分 | `get_index_stocks` |
| 个股估值与市值（PE/PB/总市值） | 东方财富 | 约 2018 年起 | `query(valuation.*)` |
| 个股财务指标（ROE/净利润增长率） | 新浪财经 | 指定年份起 | `query(indicator.*)` |
| 申万一级行业指数 | 申万宏源 | **1999 年起** | 行业指数 |
| 申万行业成分股 | 申万宏源 | 最新成分 | `get_industry_stocks` |
| 可转债日线 | 新浪财经 | 上市日起 | `get_price`（可转债） |
| 指数市盈率（月度） | 乐咕乐股 | **2005 年起** | 需自行计算 |

### 3.1 磁盘缓存（为什么第一次慢、后面快）

第一次运行某个策略时，程序会联网拉数据并把**整段历史**缓存到 `data_cache/`。
之后无论怎么改 `START` / `END`，都只读本地缓存、**不再联网**，所以是秒开。

- 缓存键 = 「标的 + 类型 + 复权方式」，**与日期区间无关**，所以 20 个策略能共享同一份缓存；
- 自动判新鲜度：缓存里最新数据比今天早 **7 天以上**时自动重新拉取；
- 手动清空缓存：

```python
from btlab.datasource import clear_cache
clear_cache()          # 清空全部
clear_cache('daily_')  # 只清日线
```

`data_cache/` 已在 `.gitignore` 中，不会进版本库，也可随时整个删掉。

### 3.2 数据层的关键设计

- **代码归一化**：`'600000'` / `'sh600000'` / `'sh.600000'` 都能识别。
  并且能正确区分 **`000001` = 平安银行（深市股票）** 与 **`sh000001` = 上证指数**——
  这是免费数据源最容易踩的坑（`000xxx` 既可能是深市股票也可能是沪市指数）。
- **防未来函数**：`btlab.runner.asof(panel, date)` 只取「不晚于调仓日」的最近一条基本面数据。
- **财务数据公告滞后**：`roe_panel(codes, lag_days=45)` 把财务"报告期"后移 45 天，
  近似还原"公告之后才能知道"的真实约束。
- **ETF 含分红口径**：新浪 ETF 接口只有不复权价，`load_daily` 会读取分红记录并**加回累计分红**
  （`adj(t) = 价格(t) + 截至 t 的累计分红`），使区间收益接近真实总收益。
  以 510300 为例（2013-01 至今）：不复权 +75%，加回分红后 +107%，同期沪深300指数 +73%。

## 4. 回测工具层（`btlab/runner.py`）做了什么

只做三件"少写重复代码"的事，**不含任何自研撮合或账务逻辑**。

### 4.1 A 股交易成本模型（与聚宽 `set_order_cost` 对齐）

| 项目 | 设置 |
|------|------|
| 佣金 | 买卖各 **0.03%** |
| 印花税 | **仅卖出**收取 **0.05%**（2023-08-28 起减半，此前 0.1%） |
| 最低佣金 | 单笔 **5 元** |
| 滑点 | 单边 **0.02%** |

实现方式是继承 backtrader 官方的 `bt.CommInfoBase`（官方扩展点），而不是改动引擎。

### 4.2 每日净值记录

`NavRecorder` 是 backtrader 官方的 `bt.Analyzer` 扩展点，逐日记录
`strategy.broker.getvalue()`，供计算绩效与画图。

### 4.3 多标的调仓骨架 `PanelStrategy`

选股类策略（要同时处理几十个数据源）统一继承 `PanelStrategy`，它做三件琐事：

1. **交易日历**：外部把基准指数日线命名为 `'__CAL__'` 一起喂进来当"时钟"。
   这样某只股票停牌时策略依然知道"今天是几号"（用某只个股当时钟会停摆）；
2. **调仓频率**：只需实现 `on_rebalance(cur_date)`，骨架按
   `monthly`（默认，每月第 1 个交易日）/ `weekly` / `daily` 自动调度；
3. **下单工具**：`equal_weight_order()`（等权）、`value_weight_order()`（按权重）、
   `close_all()`（清仓），内部自动换算整手股数与目标股数差额。

> 这是"继承 backtrader 的 `bt.Strategy` 写子类"的常规用法；
> 下单最终走 `self.buy()` / `self.sell()` / `self.close()`，
> 由 backtrader 的 `Broker` 在下一根 K 线撮合成交。

### 4.4 成交时点与未来函数

- 信号在 **第 t 日收盘后**（`next()` 里）计算，订单在 **第 t+1 日开盘**成交。
  这比"当日收盘决策、当日收盘成交"更保守，也更贴近真实；
- 聚宽版用 `run_daily(trade, time='14:50')` 在盘中触发，两者都是"收盘前决策"，逻辑等价。

## 5. 与聚宽版的差异（对照表）

B 组在数据可得性上做了必要的近似，**每个策略文件头部都写清了各自的差异**，汇总如下：

| 维度 | 聚宽原生版 | backtrader 本地版 | 影响 |
|------|-----------|-------------------|------|
| 股票池 | `get_index_stocks`（**历史时点**成分股） | 中证指数官网（**当前**成分股） | **幸存者偏差**，本地版收益偏高，仅作教学 |
| 估值数据 | `query(valuation.*)`（任意历史时点） | 东财个股估值（**2018 年起**日频） | 估值类策略回测起点为 2018-01-01 |
| 财务公告日 | 有真实公告日 | 报告期 + 45 天推定 | 事件窗口有小幅偏移 |
| 行业归属 | `get_industry(stock, date)`（历史时点） | 申万当前成分（**仅约一半行业可用**） | `bt_s08` 行业中性化维度偏弱，缺失归入"未知" |
| 转股溢价率 | 有历史序列 | 只有**当前快照** | `bt_a05` 双低退化为"以低价为主" |
| 分钟级数据 | `get_price(frequency='minute')` | 免费源不稳定 | `bt_a09` **降频为日线**短期反转 |
| 舆情文本 | 股吧 / 新闻 / 研报 | 无免费历史文本 | `bt_a10` 改用**量价情绪代理因子** |
| ETF 复权 | 动态复权（含分红） | 新浪不复权价 + **加回分红**修正 | 基本对齐 |
| 融券成本 | 可配置 | 未建模 | `bt_a03` 多空对冲高估收益 |

> 这些差异**不是 bug，而是数据源能力的边界**。教学价值在于：**同样的策略逻辑，
> 数据口径不同，结论可能完全不同**——这正是量化研究中最容易被忽视的一环。

## 6. 常见问题 FAQ

**Q1：第一次运行很慢，卡在"加载日线"？**
正常。首次要联网拉数据，选股类策略要拉 30~40 只股票，约 1~3 分钟；有缓存后秒开。
建议先跑 `bt_s01`（单标的）熟悉流程。

**Q2：报 `RuntimeError: 未取到 XXX 的行情数据`？**
该标的数据源暂时不可用（退市、尚未上市或网络抖动）。程序已内置 3 次重试；
选股类策略会自动跳过该标的并在日志里打印 `[跳过]`。

**Q3：报 `ProxyError` / `ConnectionError`？**
本机开着代理（Clash / V2Ray 等）时，部分数据源（如东方财富 `push2his.eastmoney.com`）
可能被代理拦截。可以试试：关闭代理，或把 `push2his.eastmoney.com`、`push2.eastmoney.com`
加入代理直连规则。新浪财经、中证指数、申万宏源的数据源通常不受影响。

**Q4：为什么本地版收益率和聚宽版差这么多？**
见第 5 节对照表。最常见的原因是**股票池幸存者偏差**（本地用当前成分股）
与**估值/财务数据起点不同**。想严格复现，请在聚宽云端运行 A 组。

**Q5：怎么换标的 / 换股票池？**
- 单标的策略：改文件顶部 `SYMBOL = '510300'`；
- 选股类策略：把 `load_index_members('000300')` 换成 `load_index_members('000905')`（中证500），
  或直接写死代码列表：`codes = ['600519', '000858', '601318']`。

**Q6：怎么改手续费 / 滑点？**
都是 `run_strategy(...)` 的参数：`commission=0.0003, stamp_duty=0.0005, slippage=0.0002`。

**Q7：`data_cache/` 能删吗？**
能。删了下次运行重新联网拉取（会慢一次），不影响策略逻辑。

**Q8：股票池里有些股票被跳过了？**
`load_universe()` 会剔除「上市时间太晚、覆盖不了回测区间」的标的
（否则多标的策略的 `next()` 要等到最晚上市那天才触发）。
日志会打印 `候选 N 只 → 数据可用 M 只`。

**Q9：`bt_a03` 多空对冲净值会变成负数吗？**
默认参数下不会（多空各 40% 敞口，总敞口 0.8 倍），并且策略内置了风控保险丝：
净值跌破初始资金 40% 时自动清仓停止交易。

## 8. 风险提示

- 本仓库所有策略**仅供学习量化编程与研究方法**，**不构成任何投资建议**；
- **历史回测不代表未来表现**。本地回测存在第 5 节列出的数据口径近似，
  以及幸存者偏差、未来函数、过拟合等通用风险；
- 进阶策略涉及的**融券、分钟级交易、事件驱动、可转债强赎**等在真实市场中还有
  券源限制、交易成本、流动性、条款触发等回测无法完全模拟的约束；
- 换手率高的策略请特别关注**交易成本**：绩效报告里给了"累计换手率"，
  乘以双边约 0.06% 的成本，就能直观看出成本对收益的侵蚀。
